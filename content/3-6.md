## why

模型不直接读文字，读的是 token id 序列（0-8 埋过这条线）。把字符串切成 token 的那段程序——tokenizer——看起来是最没有技术含量的组件，实际深刻影响一切：**词表大小直接写进参数账本**（嵌入层），**切法决定序列长度从而决定推理成本与有效上下文**，**同一句话在不同 tokenizer 下的 token 数可以差一倍**，中英文成本差异至今是多语言模型的一个公平性问题。本单元讲清楚 subword 为什么赢、BPE 到底在做什么、byte-level 的关键一招、三种主流算法的差异、以及词表大小的四重权衡。

## body

### 三种粒度与 OOV 困境

**词级**：按空格/标点切词，词表 = 词典。英语像 "unbelievable" 这样的变形词让词典膨胀到几十万；更致命的是 **OOV**——任何没进词典的词都变成 `[UNK]`，信息直接丢失。

**字符级**：词表 = 字母表（中文 ≈ 常用字表）。没有 OOV，但 "unbelievable" 变成 12 个 token——序列长度乘以 4~5 倍，自注意力的 \(O(L^2)\) 成本和 KV cache 全线承压。

**subword**：居中方案——高频词保持完整，低频词切成常见片段，没见过的词拆成已知片。**既无 OOV，又不爆炸序列长度**。今天所有主流 LLM 都是 subword tokenizer。

### BPE 算法：从压缩算法到 tokenizer

BPE（Byte Pair Encoding）原是 1994 年的数据压缩算法（Gage），Sennrich 等人 2016 年把它引入神经机器翻译，从此统治 NLP。训练过程出奇地简单：

1. **预分词**（见下文）得到初始词表内的"词"序列；
2. 统计语料中所有**相邻 token 对**的出现频率；
3. 把频率最高的一对**合并**成一个新 token，加入词表；
4. 重复 2~3，直到词表达到目标大小 \(V\)。

以词表 {"l o w e r n s t i d"} 上的一批小词为例：初始序列 "l o w / l o w e r / n e w e s t"。第一轮最高频的相邻对是 "l o"（出现多次）→ 合并为 "lo"；下一轮可能是 "lo w" → "low"；…… 最终高频的完整词（"low"）与高频片段（"er"、"est"）都会进入词表。**高频组合优先生成**——这正是 subword 的定义。

推理时编码同样用这套规则：对每个词，按训练学到的**合并优先级**贪心应用。同一个词表的编码结果是确定的、可复现的。

### byte-level BPE：GPT-2 的关键一招

字符级 base 词表有个隐患：Unicode 有超过 100 万个码位，任何"常用字符集"都会漏（emoji、生僻字、乱码、跨语言文本）。GPT-2 的解法优雅而彻底——**base 词表只用 256 个字节**：任何文本先编码成 UTF-8 字节流，再在字节序列上跑 BPE。

好处：**世界上任何字符串都能编码，永远不会有 UNK**。代价：罕见字符被展开成 1~4 个字节 token——这就是为什么一个 emoji 在 API 计费里常常价值好几个 token。GPT-2 的 pre-tokenizer 正则（按字母、数字、标点、空白分类，空格附着到后续 token）配合字节级 BPE，成为后续 GPT 系、Llama、Qwen 的标配。

### 三种 subword 算法对比

| | **BPE** | **WordPiece** | **Unigram** |
|---|---|---|---|
| 方向 | 从小词表**向上合并** | 同 BPE（自底向上） | 从大词表**向下删减** |
| 准则 | 相邻对频率最高 | 使训练似然增量最大 | 删除后总 loss 上升最少 |
| 代表模型 | GPT、Llama、Qwen | BERT、Electra | T5、ALBERT |
| 特色 | 简单、流行 | BERT 的 `##` 续接记号 | 天然带子词概率，可做 subword regularization |

Unigram 先备一个超大候选词表，再反复删除"对语言模型 loss 贡献最小"的 token，保留 \(V\) 个；因为每个 subword 都带概率，还可以采样出不同的切分做数据增强（Kudo 2018）。三者工程质量在今天已经收敛，选谁更多是生态兼容问题（模型与分词器必须成对）。

### 预分词与特殊 token

**预分词**（pre-tokenization）是 BPE 的第一道工序：先用正则把文本切成不允许跨越的"词块"（GPT-2 把数字、字母、标点、空白分开）。没有它，"trust" 与 "trusting" 的片段会跨词错配，合并结果不可复现。SentencePiece 更激进——**不依赖预分词**，把空格编码成前缀符号（`▁`）后直接在原始文本上跑算法，天然语言无关、可逆无损。

**特殊 token**不走 BPE，直接进词表：`[BOS]`、`[EOS]`、`[PAD]`、`[UNK]`、`<|endoftext|>`、以及对话模板用的 `<|user|>`、`<|assistant|>`。它们承担结构性职能（起止、填充、分隔、角色），任何语料统计都不该产生它们。

### 词表大小的四重权衡

主流词表从 32k 到 152k 不等（GPT-2 50k、Llama 32k→128k、GPT-4 约 100k/200k、Qwen 152k），选 \(V\) 要同时看四笔账：

1. **参数账**：输入嵌入 + 输出投影共 \(2\times V\times d\)（若权重共享则减半）。\(V\) 从 32k 到 128k，对 1B 模型是 65M vs 260M 参数——**词表直接写进 3-0 的参数账本**。
2. **序列长度账**：\(V\) 越大，一个词被切得越碎的概率越低（fertility 越低），序列越短。英语约 0.75 词/token 是常见水位；序列短 = 注意力计算省、同上下文能装更多内容。
3. **多语言公平账**：Ahia et al. 2023 发现，同等语义内容，非拉丁语言的 token 数显著更多（fertility 高 1.5~3 倍）——推理更贵、上下文浪费更多、且 API 按 token 计费时更不公平。中文是重灾区之一：常用字单字常独立成 token，词语才合并，一段中文的 token 数常接近字符数的 1~1.5 倍，而同内容英语只要 1/4 左右。
4. **训练充分账**：\(V\) 越大，长尾 token 分到的训练样本越少，稀疏 token 的嵌入训不充分——所以词表不是越大越好，128k 以上的收益递减明显。

### tokenizer 与模型行为

tokenizer 的切法会在模型能力上留下可见的指纹：GPT 系模型数不对字符串里的字母（它看到的是 token 不是字符）、算术在某些 tokenizer 下更容易（数字按位切开 vs 整块）、代码的特殊符号依赖预分词规则。**同一个"模型"换 tokenizer 不是透明操作**：词表变了，嵌入层要么重训要么做迁移映射，行为会漂移——这是继续训练/扩展词表时的经典工程题（Llama 3 扩词表到 128k 就是先扩词再退火）。

### 判断框架

拿到一个 tokenizer，问三个问题：

1. **算法与字节层**：BPE/WordPiece/Unigram？byte-level 吗（决定 UNK 会不会出现）？
2. **词表与 fertility**：\(V\) 多大？目标语言的 fertility 是多少（同样内容多少 token）？
3. **特殊 token 与模板**：有哪些特殊 token？对话模板怎么拼（角色 token 是否完备）？

## ex

**练习 1（对应退出标准 1）**
描述 BPE 的训练算法，并说明它为什么天然产生"高频整词、低频碎片"的 subword 分布。

%%%

**参考答案：**
算法：① 预分词得到词块序列；② 统计所有相邻 token 对频率；③ 合并最高频的一对为新 token 入词表；④ 重复至词表达到目标大小。高频组合（无论是完整词还是常见片段）在所有相邻对里出现频率最高，因此被优先合并——合并优先级本质就是频率排序，自然形成"高频整词、低频拆片"的 subword 分布。

**练习 2（对应退出标准 2）**
byte-level BPE 解决了什么问题？代价是什么？

%%%

**参考答案：**
解决：字符级 base 词表覆盖不全的问题。base 只用 256 字节，任意 UTF-8 文本都能编码，**永远无 UNK**。代价：罕见字符、emoji、乱码被展开成多个字节 token，序列变长、计费变贵；同时字节表示让预分词与合并规则更依赖精心设计的正则。

**练习 3（对应退出标准 3）**
对比 BPE、WordPiece、Unigram 三种算法在方向、准则与代表模型上的差异。

%%%

**参考答案：**
BPE：自底向上合并相邻对、按频率，代表 GPT/Llama/Qwen。WordPiece：同样自底向上，但合并准则为使训练似然增量最大，代表 BERT（用 `##` 表示续接）。Unigram：自顶向下，从大候选词表删除对 loss 贡献最小的 token，代表 T5/ALBERT，天然带子词概率、可做 subword regularization。

**练习 4（对应退出标准 4）**
词表大小 \(V\) 的四重权衡是什么？为什么"词表不是越大越好"？

%%%

**参考答案：**
① 参数账：嵌入+输出 \(2Vd\)（权重共享减半），V 翻倍参数线性涨；② 序列长度账：V 大则 fertility 低、序列短、推理省；③ 多语言公平账：非拉丁语言 fertility 更高，同样内容 token 更多，推理贵且不公平（中文尤其）；④ 训练充分账：V 越大长尾 token 训练样本越少、嵌入训不充分。综合看 128k 以上收益递减，所以主流停在 32k~152k。

**练习 5（对应退出标准 5）**
预分词的作用是什么？特殊 token 为什么不能由 BPE 统计产生？给一个已有模型换 tokenizer 会有什么后果？

%%%

**参考答案：**
预分词先用正则把文本切成不允许跨过的词块，保证合并规则可复现、不跨词错配（GPT-2 的字母/数字/标点分类）。特殊 token 承担结构职能（起止、填充、角色分隔），必须精确匹配、不参与统计合并，否则会被切碎或消失。换 tokenizer 意味着词表与嵌入全部变化，旧嵌入要么重训要么做迁移映射，模型行为会漂移——必须重做退火验证。
