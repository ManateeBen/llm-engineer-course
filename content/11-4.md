## why

推理部署的数学在 8-7（KV cache 与调度）、8-8（量化与投机解码）已经全部就位，8-0 §4 还给了判区方法。国产化部署不是新学科——**是同一套方法论在新参数下的重新核算**：roofline 的 \(P_{\max}\) 与 \(B_{\max}\) 换成 NPU 的实测值，量化档位看硬件原生支持（11-0 的低精度单元），服务化语义（OpenAI 兼容 API、PD 分离）更是厂商无关。本单元讲三件真正"国产特有"的事：引擎栈的分层、量化的硬件原生档、以及"方法论过河"的完整 worked example。

## body

### 1 引擎栈：分层与两条路线

国产推理栈的分层（对照 8-7 的 vLLM 架构）：

\[
\underbrace{\text{API 服务层}}_{\text{OpenAI 兼容 / 业务路由}}
\to\underbrace{\text{调度层}}_{\text{batch / KV cache 管理}}
\to\underbrace{\text{执行层}}_{\text{图执行 / 内核}}
\to\underbrace{\text{算子层}}_{\text{厂商算子库（CANN 等）}}
\to\underbrace{\text{硬件}}_{\text{NPU}}
\]

两条工程路线：

- **移植主流引擎**（vllm-ascend、SGLang NPU 后端）：把 vLLM 的调度层、PagedAttention、continuous batching 保留，只把执行层换成 NPU 后端。**收益**：调度语义、API 生态与 CUDA 世界一致；**成本**：引擎的算子假设（flash-attn 接口形状、量化 kernel）要逐个对齐——11-2 的五步法在此逐项落地。
- **原生引擎**（MindIE 等）：厂商按硬件特性从执行层向上自建（例如把图编译、低精度单元调度做成一等公民）。**收益**：能吃到硬件独有能力；**成本**：生态与工具链自成一界。

**判断口径**：调度层是厂商无关的（排队论、KV 账本都是数学），执行层以下是厂商专属的。**越往上走移植越便宜**——这也是为什么移植路线先做 vLLM 而不是先做 CUDA 二进制翻译。

### 2 量化：档位与硬件原生支持

8-8 的量化误差框架（\(\mathrm{Var}(\hat x-x)=s^2/12\) 均匀量化 + 离群值修正）完全通用，国产侧的特殊性在**硬件原生档位**：

- 权重 W8A8/FP8：NPU 的矩阵单元若原生支持 INT8/FP8 混合累加（11-0 的低精度单元），量化在**算力受限的 prefill** 上直接翻算力；decode 带宽受限则受益于**权重字节减半**（8-0 §4 的带宽账）
- KV cache 量化（INT8/FP8）：直接乘大 8-7 的 KV 账本容量，长上下文/高并发场景收益最大
- **验证纪律**：量化后的精度评估必须走 7-0 的 benchmark 流程（不能只看 ppl）；离群值敏感的层（8-8 的离群维度）保留高精度

### 3 Worked example：把 8-7/8-8 的账在 NPU 上重算一遍

设某 NPU 卡（示意口径，**真实参数以官方数据手册为准**）：BF16 峰值 \(P_{\max}\)、HBM 带宽 \(B_{\max}\)，用与 8-0/8-1 相同的算式：

**第一步·判区**（8-0 §4 方法）：decode 单 token 的算术强度 \(I\approx\tfrac12\min(M,N)\)，\(M=1\) ⇒ 深陷带宽受限 ⇒ **decode 耗时下界 = 权重字节 ÷ \(B_{\max}\)**，与 \(P_{\max}\) 无关。

**第二步·量化决策**：W8A8 把权重字节减半 ⇒ decode 下界直接减半。**注意这不是 NPU 特有结论**——8-8 的账在 CUDA 上一样成立；NPU 特有的是"FP8 矩阵单元是否原生、精度档是否有损耗"。

**第三步·并发与 KV**（8-7 账本）：KV cache 字节 \(=2\times L\times s\times d\times n_{kv}\times\) 字节宽。量化 KV 减半、MLA 压缩（3-3）再降一个量级——**这两个手段厂商无关**。

**第四步·服务化**（8-7 §调度）：PD 分离、continuous batching、前缀缓存全部照搬；唯一国产特有项是**拓扑**——prefill 组与 decode 组的卡间网络规格决定分离的通信税（8-5 的公式重测参数）。

**方法论总结**：把 8-0/8-7/8-8 的三个账本（算力账、KV 账、误差账）各抄一遍、替换参数，就是一份国产部署方案。**这也是本课程把方法论做成"参数化公式"的原因：参数会过时，公式不过时。**

### 4 服务化语义与评测口径

- **API 层**：OpenAI 兼容协议已是事实标准，业务代码零成本切换；国产特有项是合规层（内容安全过滤、日志留存——6-7 的语境）
- **评测四层**（承 11-0 的框架）：算子 micro-bench → 单卡端到端（tokens/s、TTFT、TPOT）→ 集群服务化（并发-SLO 曲线、排队论口径 8-7）→ 真实业务负载回放。**跨厂商对比必须锁四层口径**，只报单层是常见的话术空间
- **数据时间点**：本单元的引擎与后端格局以 2026-10 公开资料为准，具体版本能力以官方文档为据（spec §10 约束）

## ex

**练习 1（对应退出标准 1）**
画出国产推理栈五层结构，标注"哪些层厂商无关、哪些层厂商专属"，并解释为什么移植路线（vllm-ascend 类）先做调度层而不是执行层。

**参考答案：**
API 服务层、调度层（batch/KV 管理）= 厂商无关（纯数学与协议）；执行层、算子层 = 厂商专属（ISA、算子库）。移植先做上层：调度层是吞吐的大头（continuous batching、PagedAttention 的收益在 8-7 已量化），且与硬件无关可直接复用；执行层下沉后逐算子对齐（11-2 五步法），每对齐一个算子收益立现。**自下而上移植则一开始就陷入算子海，长期看不到端到端效果。**

**练习 2（对应退出标准 2）**
decode 带宽受限的推导在国产 NPU 上要不要重推？给"权重 28 GB、\(B_{\max}=1.6\times10^{12}\) Byte/s（示意）"的 decode 单 token 耗时下界，并算 W8A8 量化后的改善。

**参考答案：**
推导不用重做——判区逻辑（8-0 §4）只依赖"算术强度 ≪ 临界值"这一事实，与厂商无关。下界 \(=28/1.6\times10^{12}=17.5\,\text{ms/token}\)。W8A8：权重 14 GB ⇒ 8.75 ms，**提速 2 倍**（理想；实际要算 KV 与激活的搬运占比，8-7 的账本）。**对比 CUDA 卡同算式换参数即可——方法论参数化的直接红利。**

**练习 3（对应退出标准 3）**
KV cache 账本：模型 \(L=80, s=16384, d=7168, n_{kv}=1\)（MLA 压缩前的 MHA 等效口径按 \(n_{kv}\) 个 KV 头、每头 128 维计）。BF16、无压缩的 KV 总量多少 GB？INT8 量化后？再说明为什么"长上下文高并发"是量化 KV 收益最大的场景。

**参考答案：**
每 token KV \(=2\times80\times1\times128\times2\,\text{B}=40960\,\text{B}=40\) KB。16k 上下文一条 ≈ 655 MB。并发 \(b\) 条 ≈ \(b\times0.64\) GB（8 并发 ≈ 5.2 GB——还算可控；但 MHA 多头口径（\(n_{kv}=32\)）要 ×32 ≈ 21 GB/条，即爆）。INT8 减半。**长上下文×高并发时 KV 线性于 \(s\times b\) 双乘**，是账本里唯一随两者同时线性爆的项——所以收益最大。**MLA 的 \(n_{kv}\) 压缩（3-3）与 KV 量化（8-8）相乘才是完整答案。**

**练习 4（对应退出标准 4）**
部署方案要支持"8 并发、单条 8k 上下文、TTFT < 500 ms、吞吐 > 2000 token/s"。给出核算顺序（先算哪个账本、后算哪个），并解释为什么顺序错了会白做。

**参考答案：**
顺序：① KV 账本定**能不能装**（并发 × 上下文 × 每 token KV ≤ 显存 − 权重）；② 判区定**各阶段瓶颈**（prefill 算力受限 → TTFT ≈ \(2ND_{\text{prompt}}/P\)；decode 带宽受限 → 吞吐上界 ≈ \(B_{\max}/\)权重字节 × 并发效率）；③ 服务化（PD 分离、批调度）定**聚合指标**。顺序错的白做例：先堆吞吐优化（quant/spec decode）再发现 KV 装不下 8 并发——**容量是可行性约束，性能是优化问题，可行性先行。**

**练习 5（对应退出标准 5）**
厂商 A 报告"单卡吞吐 3000 token/s"，厂商 B 报"2800 token/s"。列四个必须核对的口径项，说明每个项如何翻盘。

**参考答案：**
① **序列长度与上下文**：1k 与 32k 的吞吐不可比（KV 与 attention 成本全不同）；② **并发数与 batch**：单并发吞吐低是正常的（带宽受限），高并发的聚合吞吐才有意义；③ **输入输出比**：prefill 占比不同，TTFT/吞吐的加权口径不同；④ **量化档位**：W8A8 vs BF16 的 3000 与 BF16 的 2800 不可比。**跨厂商对比的唯一安全做法：固定模型、固定负载回放、固定四层评测口径（11-0）。**

**练习 6（对应退出标准 6）**
某业务在 CUDA 参考实现上验证通过，迁到 NPU 后输出质量下降。列系统侧三个嫌疑与检查方法（区分"数值路径差异"与"实现 bug"）。

**参考答案：**
① **量化口径不一致**：迁移时默认打开了 W8A8 而 CUDA 参考是 BF16——检查部署配置的精度档位，先跑同档位对比；② **算子实现的数值路径差异**（如 softmax 的归约顺序、低精度累加）：离线对同一输入比对中间张量（8-2 练习的误差传播视角，定位首个发散层）；③ **tokenizer/前后处理差异**：分词结果不同导致输入本身不同——先比对 token ids 再谈模型。**方法论：从输入端往输出端逐级 diff，首个发散点即病灶——与 11-2 的精度对齐五步法同源。**
