## why

2-3 的缩放律说"加参数就变强"，但加参数也线性加计算——直到 MoE 打破这个耦合。Mixture-of-Experts 的核心思想一句话：**把最大的 FFN 层切成很多"专家"，每个 token 只激活其中一小把**。于是总参数量（知识容量）和每 token 计算量解耦：1.8T 总参数的模型，每 token 只算 ~30B 的计算。代价是一个全新的工程难题——**路由坍缩**：不干预的话，router 会把所有 token 送给少数几个"明星专家"，其余专家饿死，模型退化。本单元讲清楚：稀疏门控的机制、负载均衡损失为什么长那样、容量因子与 token dropping 的取舍、以及 Mixtral/DeepSeekMoE 两个真实配方。这是读懂 2024 年后一线开源模型（Mixtral、DeepSeek、Qwen-MoE）的必备背景。

## body

### 从稠密到稀疏：条件计算的账

先看动机的定量版。3-0 的参数账本显示 FFN 占每层约 \(2/3\) 参数。MoE 的做法：把一个 FFN 换成 \(E\) 个并行的 FFN 专家（每个和原 FFN 同尺寸），加一个小路由器。总参数从 \(8d^2\) 涨到 \(E\times 8d^2\)，但每个 token 只过 top-\(k\) 个专家——**每 token 计算只涨 \(k\) 倍**（\(k\ll E\)）。

以 Mixtral 8×7B 为例：8 个专家、top-2、每层激活 2 个专家。总参数 47B（8×~6B + 共享部分），每 token 前向计算约 13B 参数的量——**用 13B 的计算，装 47B 的知识**。这就是"条件计算"的卖点。

### 路由器：一个会学习的调度员

路由器本身极简单——一个线性层把 token 向量 \(x\) 变成 \(E\) 个专家的分数，softmax 后取 top-\(k\)：

\[
p(x) = \text{softmax}(x W_r),\qquad \text{输出} = \sum_{i\in\text{top-}k} p_i(x)\cdot \text{Expert}_i(x)
\]

top-\(k\) 的选择是第一个设计轴：

- **top-1**（Switch Transformer）：每 token 一个专家。最稀疏、最快，但训练不稳、对路由器精度要求极高。
- **top-2**（Mixtral）：两个专家加权和。多一个专家做"平滑"，显著稳，是当前开源主流。
- **top-\(k\) 更大**：更接近稠密，收益递减。

注意路由器是**和主模型一起端到端训练的**——没有人工规则，"哪个 token 该找哪个专家"是学出来的。实证发现专家确实出现了专门化：有的专家吃代码、有的吃数学符号、有的吃特定语言（3-0 讲过 FFN 是知识驻地，MoE 把这个驻地切成专业分工）。

### 路由坍缩：不干预就退化

如果不加任何约束，训练会走向一个坏的均衡：路由器发现"把 token 送给专家 A 总能降低 loss"（A 先火 → A 数据多 → A 训得更好 → 更多 token 送过去），最终**所有 token 都挤向少数专家**，其余专家从未被训练（死专家），模型实际退化成一个稠密小模型。这叫路由坍缩（routing collapse），是 MoE 训练的第一杀手。

诊断信号：监控每个专家在 batch 内分到的 token 比例——健康的分布大致均匀（或至少不极端），坍缩时头部专家占 80%+。

### 负载均衡损失：给路由器加的税

Switch Transformer 的解药是一个**辅助损失**，加在主 loss 上：

\[
\mathcal L = \mathcal L_{\text{data}} + \alpha \cdot \mathcal L_{\text{aux}},\qquad
\mathcal L_{\text{aux}} = E\sum_{i=1}^{E} f_i\cdot P_i
\]

- \(f_i\)：batch 内分给专家 \(i\) 的 token 比例（实际负载）；
- \(P_i\)：路由器给专家 \(i\) 的平均概率（路由意愿）；
- 乘积 \(f_i\cdot P_i\) 在"负载与意愿错配"时变大——最小化它 = 逼路由器把 token 摊匀。

直觉：这是一笔"均衡税"——为了长期健康，宁愿每步损失一点点数据拟合。\(\alpha\) 通常取 \(10^{-2}\) 量级：太小压不住坍缩，太大拖累主任务。**辅助损失是 MoE 训练最经典的超参之一**，也是面试高频题。

### 容量因子与 token dropping：硬约束的代价

负载均衡损失是"软"引导，工程上还要一道"硬"保险：**容量因子**（capacity factor）。每个专家每步最多处理 \(C = \lceil \text{cf}\times T/E\rceil\) 个 token（\(T\) 是 batch token 数），超出容量的 token 被**丢弃**（该步不过任何专家，残差直通）。

- cf=1.0：恰好平均分配——任何不均衡都导致丢弃；
- cf=1.25~1.5：留 25~50% 余量，实际部署常用；
- cf 越大丢弃越少，但峰值显存/通信越紧张（专家并行时 buffer 要按最坏情况开）。

token dropping 是"用少量信息损失换系统可控"的典型交易。有个反直觉的细节：被丢的 token 走残差旁路，不是"消失"，所以 cf=1.0 也能训练，只是每个 token 的 MoE 层贡献参差不齐。

### 工程现实：专家并行与通信

MoE 的计算特征把系统复杂度拉满：不同专家在不同 GPU 上（专家并行），每个 MoE 层有两次 all-to-all 通信（token 发往专家所在卡、结果收回）。通信量随 top-\(k\) 和卡数增长——**MoE 的吞吐瓶颈常在通信不在计算**。GShard（Lepikhin et al. 2021）奠定了自动切分框架；今天 Megatron/DeepSpeed 都有成熟 MoE 支持。

### 两个真实配方

**Mixtral 8×7B**（2024）：8 专家 top-2、无共享专家、负载均衡损失、容量因子按需。意义在于**证明了 MoE 可以开源、可以高质量**——用 13B 计算打平很多 30B+ 稠密模型，直接带火了开源 MoE 路线。

**DeepSeekMoE**（2024）：两个结构创新。① **细粒度专家**：把专家切得更小更多（如 64 个专家选 8），提高组合多样性——"用更多小专家的组合代替少数大专家"；② **共享专家**：留 1 个永远激活的"通才"专家承载通用知识，其余稀疏专家专心做专门化——减少专家间的知识冗余。配合 MLA（3-3）与多 token 预测，构成 DeepSeek-V3 的效率配方。

### 判断框架：什么时候用 MoE

用前三问：

1. **推理经济吗？** MoE 的优势是"每 token 计算小、总参数大"——适合**高并发推理服务**（计算瓶颈）而非单次生成（显存全量加载总参数，小 batch 不划算）。
2. **付得起工程税吗？** 专家并行通信、负载均衡调参、容量因子监控——基础设施不成熟的团队谨慎。
3. **数据够多吗？** MoE 的知识容量靠数据喂出来，数据不足时大总参数是浪费。

## ex

**练习 1（对应退出标准 1）**
MoE 如何解耦"知识容量"与"每 token 计算"？用 Mixtral 8×7B 的数字说明。

%%%

**参考答案：**
把 FFN 切成 \(E\) 个专家、每 token 只过 top-\(k\) 个：总参数 \(\propto E\)（知识容量），每 token 计算 \(\propto k\)（激活参数）。Mixtral：8 专家 top-2，总参数 47B、每 token 激活约 13B——用 13B 的计算装 47B 的知识。

**练习 2（对应退出标准 2）**
写出 Switch Transformer 的辅助损失公式，并解释每一项的角色。

%%%

**参考答案：**
\(\mathcal L_{\text{aux}}=E\sum_i f_i P_i\)，\(f_i\) 是 batch 内专家 \(i\) 的实际 token 负载比例，\(P_i\) 是路由器给专家 \(i\) 的平均概率。负载与意愿错配时乘积大；最小化它逼路由器把 token 摊匀，防路由坍缩。总损失 \(\mathcal L=\mathcal L_{\text{data}}+\alpha\mathcal L_{\text{aux}}\)，\(\alpha\approx10^{-2}\) 量级。

**练习 3（对应退出标准 3）**
什么是路由坍缩？它是怎么自发形成的？

%%%

**参考答案：**
路由器把几乎所有 token 送给少数专家、其余专家饿死退化的现象。正反馈机制：某专家先获得较多 token → 训得更好 → loss 更低 → 路由器更倾向送更多 token 过去 → 马太效应。不加辅助损失干预，训练自发走向这个坏均衡。

**练习 4（对应退出标准 4）**
容量因子的作用是什么？cf=1.0 与 cf=1.5 各意味着什么？被丢弃的 token 去哪了？

%%%

**参考答案：**
容量因子 cf 规定每专家每步最多处理 \(\lceil\text{cf}\cdot T/E\rceil\) 个 token，是负载均衡的硬保险。cf=1.0 恰好平均、任何抖动都触发丢弃；cf=1.5 留 50% 余量、丢弃少但峰值缓冲大。被丢弃的 token 不过专家，走残差旁路直通——不是信息消失，只是该层 MoE 贡献缺失。

**练习 5（对应退出标准 5）**
DeepSeekMoE 的"细粒度专家 + 共享专家"分别解决什么问题？一个推理服务团队该不该选 MoE，用三问框架判断。

%%%

**参考答案：**
细粒度专家（小而多）提高专家组合的表达多样性；共享专家（常激活）承载通用知识、减少稀疏专家间的知识冗余。三问：① 推理经济吗——高并发服务（计算瓶颈）适合，单次小 batch 生成不适合（总参数全量占显存）；② 工程税付得起吗——专家并行通信与调参需要基础设施；③ 数据够吗——知识容量靠数据喂，数据不足时大总参数浪费。
