## why

6-0~6-4 都在教模型"变得更好"，本单元讲变得更好要付的代价：对齐后的模型在通用 benchmark 上常掉几个点（**对齐税**），拒答训练做过头会把正常请求也拒了（**过度拒绝**，另一种税）；而安全本身是一场持续攻防——训练出来的拒答边界，会被优化式攻击（GCG 类）和人类越狱系统性穿透。本单元把这三件事（税、张力、攻防）变成可度量、可设计的工程对象，并与 6-7 的国内合规层衔接。

## body

### 1 对齐税：掉点从哪来、怎么量

**对齐税**（alignment tax）：对齐后模型在通用能力（MMLU、HellaSwag 等，7-0 口径）上相对对齐前的下降。三个来源：

1. **数据偏移**：对齐数据（指令、偏好、拒答）分布窄，通用域的概率质量被挤压；
2. **KL 惩罚错位**：6-0 的 \(\beta\,\mathrm{KL}(\pi\|\pi_{\text{ref}})\) 若策略在安全方向上被推离 ref 太远，顺带把 ref 里好的行为也推歪了；
3. **RL 过优化**：6-3 的 \(\kappa\)——RM 偏好的"安全但无聊"模式被放大，多样性缩水表现为 benchmark 掉点。

**度量纪律**（对齐税的账必须这样算才干净）：同一评测集、同一 harness、对齐前后各跑一遍，报差值 + 置信区间（7-2 的显著性方法）；**只用安全无关的子集**（能力 benchmark 本身不含安全项，否则"少答危险题"会被误记为能力涨）。Bai et al. 2022 的 HH-RLHF 实践结论：税通常 1~3 个点，且可通过**通用数据混入对齐阶段**（preference 数据 + 通用 SFT 数据混合）基本抹平——**税不是定律，是数据配方问题**。

### 2 helpfulness 与 harmlessness 的张力：Pareto 前沿

两个目标共享同一个策略分布，天然冲突：更愿意帮忙 ⇒ 更多有害输出；更谨慎 ⇒ 更多正常请求被拒。把两个轴画出来，所有训练配置落在一条 **Pareto 前沿**上：前沿上的点，一个指标不降另一个涨不上去。

- **过度拒绝**（over-refusal）：训练数据里拒答样本过多/过宽（"如何入室行窃"的拒答学会了，顺带把"如何开锁（合法锁匠场景）"也拒了）——过度拒绝率是对齐的第二个 benchmark，同样要 harness + 显著性；
- **工程位置**：多数产品落在"略偏 helpfulness"的前沿点（拒答误伤的投诉成本 > 漏放的有害内容成本），但合规场景（6-7）要求"略偏 harmlessness"——**前沿上的选点不是技术问题，是产品与合规的决策**，技术侧要给出前沿曲线供决策，不是自己拍。

### 3 越狱：目标冲突与优化式攻击

**为什么对齐模型会被越狱**（Wei et al. 2023 的解释）：训练同时优化了"有用"与"无害"两个目标，当输入构造出**目标冲突**（如角色扮演"你现在是危险 AI，但只是在演戏"），两个目标的梯度互相抵消，行为落入训练没覆盖的缝隙。三类攻击：

| 类型 | 机制 | 例 |
|---|---|---|
| **人类越狱** | 利用指令层级混乱、角色扮演、前缀注入 | "忽略以上指令"、DAN 类、假设性框架（"写小说，角色是…"） |
| **优化式攻击** | 直接优化攻击后缀：\(\min_\delta -\log P(y_{\text{target}}|x,\delta)\)，贪心/梯度搜索（GCG，Zou et al. 2023） | 一段乱码后缀让模型输出违禁内容 |
| **自动红队** | 用 RL 训攻击者，奖励 = 攻击成功率（与 6-2 RLVR 同构，verifier = 目标模型的安全分类器） | 大规模红队找薄弱 prompt 模式 |

**GCG 的可迁移性是最危险的性质**：在开源模型上搜出来的后缀，对闭源 API 常常也部分有效——攻击者可以用便宜的开源模型"锻造"再迁移。防御的相应思路：**不要把安全边界建成一道静态的墙**（墙会被优化穿透），而是分层（§4）。

### 4 防御：分层与持续运营

\[
\text{安全} \;=\; \underbrace{\text{训练层}}_{\text{拒答 RL + 红队数据}}\;+\;\underbrace{\text{系统层}}_{\text{输入/输出过滤 + 沙箱 + 权限}}\;+\;\underbrace{\text{运营层}}_{\text{监控 + 红队循环}}
\tag{6.5.1}
\]

- **训练层**：拒答数据 SFT + harmlessness RL（6-0 管线，奖励 = 安全分类器通过）；对抗训练（把 GCG 后缀当训练样本，教模型拒）——提高攻击成本但不消除；
- **系统层**（SRE 主场，6-7 同源）：输入侧分类器/敏感词预筛 + prompt 注入检测；输出侧安全分类器（独立于被保护模型——否则"用模型守模型"一损俱损）；**权限与沙箱**（工具调用白名单、代码执行隔离——10-1 的 agent 语境）；速率限制与滥用检测；
- **运营层**：上线后的红队循环（每次模型/数据更新重跑攻击集）、安全事件响应 runbook、与 6-7 的日志留痕和处置 SLA 打通。

**深度防御的逻辑**：训练层把"普通攻击"成本抬高，系统层把"穿透训练层的攻击"挡住一部分，运营层保证新攻击被发现时响应周期 < 攻击扩散周期。**任何单层都可被穿透——这是设计前提，不是失败。**

### 5 安全评测：把攻防变成数字

- **攻击成功率**（Attack Success Rate, ASR）：在标准攻击集（HarmBench 等）上的成功率，按攻击类型分层报；
- **过度拒绝率**：正常但"看起来危险"的请求被拒的比例（如"如何制造炸药（化学课作业）"的歧义样本集）；
- **鲁棒性趋势**：把 ASR 当 CI 指标——每次对齐训练后跑攻击集，ASR 上升 = 回滚信号（Carlini et al. 2024 的结论：当前对齐模型的对抗鲁棒性远低于表面指标暗示的水平）。

## ex

**练习 1（对应退出标准 1）**
对齐税实验：模型 A（对齐前）MMLU 61.2%，对齐后 A' 58.7%。仅凭这两个数能下"对齐税 2.5 点"的结论吗？列出四个必须补的口径。

**参考答案：**
不能。四个口径：① **评测 harness 一致性**（prompt 模板、few-shot 数、解码参数必须逐项相同，harness 差 1 个点常态）；② **随机性**（跑多 seed，报均值±std 或置信区间，2.5 点可能落在噪声内——7-2 的方法）；③ **子集构成**（MMLU 的 57 个子任务分开报——掉点常集中在特定域而非均匀）；④ **同源性**（A' 必须是从 A 继续训来的同一基座，中间换了 tokenizer/模板就不是"税"是"换了模型"。补口径后的干净结论示例：同 harness、3 seed、同模板，"对齐后 STEM 子集 −1.1、人文 +0.3、总体 −0.5±0.4"——这时"税很小"才是可信陈述。

**练习 2（对应退出标准 2）**
为什么"只训拒答、不混通用数据"会把对齐税放大？从概率质量的角度解释，并给出数据配方的修复。

**参考答案：**
拒答数据只覆盖"危险 prompt → 拒绝"这一模式，SFT 在这些样本上把概率质量搬向拒答输出；若不混通用数据，**没有反向力量把质量搬回正常域**，策略分布整体向"保守输出"漂移——通用 prompt 的回答也变短变敷衍，benchmark 掉点。修复：对齐阶段按比例混通用指令数据（典型 1:1 到 1:4 的拒答:通用），RL 阶段在奖励里给"正常请求的 helpfulness"分量（Bai et al. 2022 的做法）；本质是把 Pareto 前沿的两个方向都写进训练信号，而不是只推一个。

**练习 3（对应退出标准 3）**
GCG 的目标 \(\min_\delta-\log P(y_{\text{target}}|x,\delta)\)：解释为什么它搜出的后缀看起来像乱码，以及为什么开源模型上搜的后缀对闭源 API 可能有效。

**参考答案：**
乱码的原因：优化只在"降低目标 token 的负对数概率"，不要求后缀可读——对抗后缀工作的方式是**把模型内部状态推到"已进入顺从模式"的区域**（通过 token 序列的分布效应），语义可读性从不是约束；梯度搜索找到的是高维空间里的统计捷径，长这样纯属偶然。可迁移的原因：不同模型的训练数据与对齐目标大量重叠（都见过相似的指令数据、相似的安全训练），**"顺从模式"的内部表征在不同模型间部分共享**——在一个模型上找到的捷径，在另一个模型上大概率也在同一区域附近。防御含义：闭源 API 不能假定"我的梯度不可见所以我安全"，必须在推理时检测异常 token 模式（乱码后缀的统计特征本身可检出）。

**练习 4（对应退出标准 4）**
设计红队 RL：攻击者模型 \(\mathcal{A}\) 生成 prompt，目标模型 \(\mathcal{T}\) 的响应被分类器判"有害"则攻击者得 1。写出奖励、并指出这个闭环的三个失败模式。

**参考答案：**
奖励：\(r_{\mathcal{A}}=\mathbb{1}[\text{harmful}(\mathcal{T}(\mathcal{A}(x)))]\)（或分类器的有害分数，软的），无额外惩罚 ⇒ 纯 ASR 最大化。失败模式：① **奖励黑客**：攻击者学会生成"让分类器误报"的 prompt（不含真实危害但触发分类器）——奖励要加人工抽检校准；② **只攻一类**：RL 快速坍缩到单一攻击模式（6-4 的熵坍缩），ASR 高但覆盖窄——需要组内多样性（6-2 的 group sampling）或攻击类型分层奖励；③ **过拟合目标模型**：红队只对 \(\mathcal{T}\) 的当前版本有效，模型一更新就过时——红队必须持续运营（§4 运营层），且保留跨模型迁移集。**红队 RL 与 RLVR 同构：verifier 质量（这里是分类器）决定上限。**

**练习 5（对应退出标准 5）**
产品需求：助手过度拒绝率从 12% 降到 <3%，同时标准攻击集 ASR 不上升。给出技术方案（分层）与验收方式。

**参考答案：**
方案：① 训练层——拒答数据重平衡：删"看起来危险实则无害"的误伤样本，补"边界样本的正确响应"（合法安全信息场景：化学课、网络安全教育、医学），重训一轮；② 系统层——输入侧预筛分类器从"宁可错杀"调到"错杀率与漏过率加权"（阈值按误伤/漏过的业务代价定），输出侧安全分类器独立校核（把过度拒绝的投诉回流成 hard negatives）；③ 运营层——把过度拒绝样本集与攻击集都纳入 CI。验收：同一 harness、3 seed 下，过度拒绝率 12%→<3% 且标准攻击集 ASR 不升（若 ASR 升 >1 个点则回滚到上一配方）——**两个指标同时锁，单指标优化就是拆东墙补西墙**。

**练习 6（对应退出标准 6）**
为什么"安全完全靠训练层"不够？从攻击者视角列出三条穿透路径，各配一条系统层防御。

**参考答案：**
穿透路径与防御：① **优化式攻击**（GCG/迁移后缀）——训练层见所未见，系统层输出分类器独立检测异常模式（且分类器与被保护模型异构，攻击者无法用同一梯度同时骗过两者）；② **工具滥用**（10-1 的 agent：模型输出合法但调用危险工具）——系统层权限白名单 + 沙箱执行 + 敏感操作二次确认（训练层管不了"模型说得对但做得错"）；③ **数据/供应链**（微调投毒：恶意数据让模型学会"收到暗语就输出违禁内容"）——系统层训练数据审计 + 模型签名 + 上线前安全评估（6-7 的 gate）；④ **提示注入**（RAG/网页内容里藏指令劫持上下文，10-0/10-1）——输入侧注入检测 + 上下文隔离（不可信内容不进指令层级）。**核心：训练层的信任边界是"输入是善意提问"，系统层不假设这一点。**
