## why

"支持 128k 上下文"听起来像一行配置，实际上是整个技术栈的总攻。把窗口从 4k 开到 128k，你会依次撞上五道墙：RoPE 没转过这么远的角度（位置墙，见 3-1）、注意力计算量按平方涨（计算墙）、KV cache 把显存吃光（显存墙，见 3-3）、模型没见过这么长的训练文本（数据墙）、benchmark 分数虚高（评测墙）。任何一层没解决，其他层的努力都白费。本单元给你一棵**五层配方树**：位置层、架构层、系统层、数据层、评测层，以及每一层的代表技术。学完后你能读懂任何一份"长上下文模型"的技术报告，并知道该用什么评测去戳破它的宣称。

## body

### 五道墙：为什么长上下文是一个系统工程

先算显存这笔账。KV cache 的字节数（BF16、每 token）：

\[
\text{KV} = 2\cdot 2\cdot L_{\text{层}}\cdot d_{\text{kv}}\cdot n_{\text{kv 头}}\cdot \text{ctx}
\]

两个 2 分别是"K 和 V"与"每元素 2 字节"。3-3 算过 7B/8k ≈ 4.3 GB；同一模型开到 128k，就是约 **68 GB**——超过单张 A100 的容量，模型权重还没算进来。系统层的优化（量化、分页）直接把这道墙的高度减半。

其余四道墙同样硬：位置墙（外推失效）、计算墙（\(O(L^2)\)）、数据墙（长文本稀缺）、评测墙（NIAH 虚高）。**没有银弹，只有配方。**

### 位置层：让 RoPE 转得更远

3-1 的结论是：RoPE 的外推失效源于"没转过的角度"。补救路线的共同思想是**让训练时见过的位置分布覆盖推理时的位置分布**：

- **PI（Position Interpolation）**：把旋转角整体除以 \(s\)，\(\theta_i\to\theta_i/s\)，长位置被压回训练范围。简单有效，但所有维度一起压缩，高频维度（本来间隔就近）的旋转分辨率被牺牲。
- **NTK-aware**：只放大 base（如 \(10000\to 10^5\)），等效于只压缩低频维度、不动高频——"高频看局部要精细，低频看全局可以粗"。
- **YaRN**：按波长分档：高频维度保持原样、低频维度插值、中频平滑过渡，再给注意力 softmax 加温度修正。少量微调即可恢复。
- **LongRoPE**：用进化搜索为两个频段分别找最优 base，配合**渐进式扩展**（4k→8k→…→2048k 逐步训练），把上下文推到 200 万 token，且长文本继续训练只用不到 1% 的原始算力。

这条线的统一认知：**外推问题本质是分布不匹配**——解法要么"改编码去够训练分布"（PI/NTK/YaRN），要么"扩训练分布去够推理"（退火，见数据层）。

### 架构层：让每层看得更省

- **滑动窗口注意力**（Mistral）：每 token 只看邻近 \(W\) 个 token，单层计算 \(O(L\cdot W)\)。感受野靠层数堆出来：32 层 × 4096 窗口 ≈ 128k 有效覆盖。短距离精细、长距离依赖交给上层。
- **Attention sink 与 StreamingLLM**：实验发现前几个 token（尤其 BOS）吸走了巨量注意力质量。机制不难理解：softmax 权重**和为 1**，当当前 token 没有合适内容可看时，"无处安放"的概率质量就丢给初始 token——它成了注意力的垃圾桶。窗口一旦滑掉这些 sink token，模型立刻崩。StreamingLLM 的解法：保留前 \(k\) 个 sink token + 滚动窗口，实现**恒定内存的无限流式推理**。代价：sink 不承载语义，长程精确检索能力弱——适合流式对话，不适合长文档问答。
- **线性注意力 / SSM**：把注意力改造成递归形式，每步 \(O(1)\)——这是 3-7 的主题，此处只做交叉引用。

### 系统层：KV cache 的账与省

3-3 讲过结构性方案（MQA/GQA/MLA 减少缓存的头数）；这里补三个工程杠杆：

- **KV cache 量化**：把缓存压到 INT8/INT4（KIVI 等工作），显存直接降 2~4 倍，精度损失可控；
- **PagedAttention**（vLLM）：像操作系统分页一样管理 KV 块，消灭显存碎片，显著提高并发——3-3 已埋线；
- **FlashAttention**：不减少显存峰值，但用分块重计算把 HBM 读写量降一个量级，长上下文不至于 OOM、训练吞吐大幅提升。注意它优化的是 IO 而非渐近复杂度。

### 数据层：长文本退火

长上下文能力**一半是训出来的**。常见配方（如 Llama-3.1、Qwen2.5 的长文本阶段）：

1. **长文档继续训练**：预训练末尾掺入数万亿 token 的长文档（书籍、代码库、长网页），先把 RoPE 见过的长度分布拉长；
2. **课程式位置扩展**：先在 8k 退火，再 32k，再 128k——每阶段都能重算 loss 曲线、及时回滚；
3. **文档级打包**：把多篇短文档拼成长序列时必须做**文档边界掩码**，防止跨文档注意力互相污染——"为省算力而拼"的 trick，处理不好就是隐形数据污染。

关键实证：**大多数模型只需要原始预训练百分之几的长文本 token** 就能把有效上下文扩一个量级——长上下文主要是"激活已有能力"而非"从零学会"。

### 评测层：benchmark 会撒谎

**NIAH（大海捞针）**：把一句无关的话埋进长文本，问模型这句话是什么。Kamradt 2023 用它对一线模型施压，但用它筛模型会犯三个错：

1. **分数虚高**：短上下文就接近满分的模型，NIAH 全过不代表真懂长文；
2. **迷失在中间**：准确率随针的位置呈 U 型——开头结尾高、中间塌陷（"lost in the middle"），因为中间位置既没有近因优势也没有首因优势；
3. **任务太浅**：针与问题语义孤立，不需要全局聚合、多跳推理。

**RULER**（Hsieh et al. 2024）把评测做成四类递进任务：检索（多针、变量名替换）、多跳追踪（变量链）、聚合（统计高频词）、长文 QA。它发现一个刺眼的规律：**宣称 32k 的模型，RULER 上的有效上下文往往只有 4k~8k**——宣称值与有效值之间有一道深渊。**LongBench** 则用双语真实长文（论文、法律、代码）做多任务横评，更贴近应用。

评测层的工程结论：宣称上下文 ≠ 有效上下文；压测用 RULER/LongBench；看曲线别看得分，注意中间位置的塌陷。

### 把五层装回一棵配方树

| 层 | 问题 | 代表技术 | 3-x 交叉引用 |
|---|---|---|---|
| 位置 | RoPE 没转过这么远 | PI / NTK-aware / YaRN / LongRoPE | 3-1 |
| 架构 | 每层看得太贵 | 滑动窗口 / attention sink / 线性注意力 | 3-7 |
| 系统 | KV cache 吃显存 | MQA/GQA/MLA、KV 量化、PagedAttention、FlashAttention | 3-3 |
| 数据 | 没见过长文本 | 长文档退火、课程式扩展、文档边界掩码 | 2-2 |
| 评测 | 分数虚高 | NIAH（有坑）、RULER、LongBench | — |

一个典型"128k 模型"的配方读法：预训练末期掺长文档退火 → YaRN/LongRoPE 改位置 → GQA 减 KV 头 + FlashAttention + 8-bit KV cache 部署 → 用 RULER 而非 NIAH 验收。**每一层单独都撑不起"128k"，合起来才行。**

### 判断框架：三问

1. **你的"长"是多长？** 8k 是工程问题（KV cache 优化即可），128k 要动位置与数据层，1M 要上线性注意力或 sink 类架构改造。
2. **读一次还是流不停？** 长文档问答要长程检索（ sink/窗口方案不适用），流式对话要恒定内存（StreamingLLM 适用）。
3. **有效上下文测过吗？** 没被 RULER 类多任务评测过的宣称，一律按宣称值打对折处理。

## ex

**练习 1（对应退出标准 1）**
列出长上下文的五道墙，并各举一个对应层的代表技术。

%%%

**参考答案：**
① 位置墙（RoPE 外推失效）→ PI/NTK-aware/YaRN/LongRoPE；② 计算墙（\(O(L^2)\)）→ 滑动窗口注意力、线性注意力；③ 显存墙（KV cache 线性增长，7B/128k ≈ 68GB）→ GQA/MLA、KV 量化、PagedAttention；④ 数据墙（长文本稀缺）→ 长文档退火、课程式扩展；⑤ 评测墙（分数虚高）→ RULER/LongBench 替代单一 NIAH。五层必须联合作战，单层优化撑不起长上下文。

**练习 2（对应退出标准 2）**
PI、NTK-aware、YaRN、LongRoPE 四个方案共享的思想是什么？它们与"数据层退火"是什么关系？

%%%

**参考答案：**
共享思想：外推失效的本质是训练与推理的位置分布不匹配，补救要么"改编码去够训练分布"（PI 全压缩、NTK-aware 只改低频、YaRN 分频段+温度、LongRoPE 搜索最优 base），要么"扩训练分布去够推理"（数据层退火）。二者常配合使用：先退火拉长见过的长度，再用位置修改把利用率提满。

**练习 3（对应退出标准 3）**
什么是 attention sink？为什么滑掉初始 token 模型会崩？StreamingLLM 的解法与代价各是什么？

%%%

**参考答案：**
softmax 权重和为 1，当前 token 没有合适内容可看时，概率质量被丢给前几个初始 token——它们成了"注意力垃圾桶"，即 sink。滑动窗口把 sink 滑出视野后，注意力质量无处安放，模型崩。StreamingLLM 保留前 k 个 sink + 滚动窗口，实现恒定内存流式。代价：sink 不承载语义，长程精确检索能力弱，适合流式对话、不适合长文档问答。

**练习 4（对应退出标准 4）**
KV cache 量化和 FlashAttention 各解决什么问题、不解决什么问题？长文本退火为什么"只需要少量长 token"？

%%%

**参考答案：**
KV 量化（INT8/INT4）压缓存体积，直接降显存，不动计算结构；FlashAttention 优化 HBM 读写（IO），不减少显存峰值、也不改 \(O(L^2)\) 渐近复杂度。长文本退火见效快，因为长上下文主要是激活预训练已有的能力（位置泛化、局部注意力模式），而非从零习得——所以几万亿长 token 的继续训练即可扩一个量级。

**练习 5（对应退出标准 5）**
只用 NIAH 评测长上下文模型会犯哪些错？RULER 发现了什么规律？

%%%

**参考答案：**
三个错：① 分数虚高——短上下文即接近满分，NIAH 全过不代表真懂长文；② 迷失在中间——准确率随针位置呈 U 型，中间塌陷；③ 任务太浅——不需要全局聚合与多跳推理。RULER 用检索/多跳/聚合/QA 四类递进任务评测，发现宣称 32k 的模型有效上下文常只有 4k~8k。结论：宣称上下文 ≠ 有效上下文，应看 RULER/LongBench 曲线而非单一 NIAH 得分。
