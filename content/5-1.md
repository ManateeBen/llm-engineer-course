## why

2-4 讲了临界 batch size，给了一个"每个规模有个最优 batch"的结论。但落到真机训练，**batch size 不是你想设多大就设多大**：一张 80GB 的卡，塞不下一个大 batch；一段 32K 的序列，注意力显存是序列长度的平方级开销。于是工程上出现三个量被绑死：

- **micro-batch**：单卡一次前向的样本数（受显存硬约束）
- **梯度累积步数（accumulation）**：跑几步 micro-batch 才更新一次
- **有效 batch**：\(\text{batch}_{\text{eff}} = \text{micro} \times \text{accum} \times \text{DP}\)，决定优化动态的"真 batch"

本单元把"batch 受什么限制、序列长度怎么影响它、三者如何换算"讲清楚——这是所有真机训练的第一道工程算术题。

## body

### 三个量的账本关系

最易被混淆的是"batch size"这个词在不同语境指不同东西。明确划分：

\[\text{batch}_{\text{eff}} = \underbrace{\text{micro\_batch}}_{\text{单卡前向}} \times \underbrace{\text{grad\_accum}}_{\text{累积步}} \times \underbrace{\text{data\_parallel}}_{\text{卡数}}\]

- **micro-batch**：单卡每次前向/反向处理的样本（或 token）数。它由**单卡显存**决定，是硬上限。
- **grad-accum**：在不更新权重的情况下，连续跑几步 micro-batch 再求平均梯度、做一次更新。它让"有效 batch"变大而**不增加峰值显存**。
- **data-parallel（DP）**：并行卡数。每张卡各算一个 micro-batch，梯度 all-reduce 求平均。

举例：8 卡、micro-batch=4、accum=8，则有效 batch = 4×8×8 = 256。优化器看到的 batch 是 256，**但任何一张卡的瞬时显存只承载 4**。

#### 梯度累积是"精确"而非"近似"

正文那句"accum 与直接大 batch 几乎等价"其实可以更强：**在累积期间不更新参数的前提下，它是恒等变形**。理由只有一条——**微分算子是线性的**，梯度算子 \(\nabla_\theta\) 对求和满足

\[
\nabla_\theta\Bigl(\frac{1}{K}\sum_{k=1}^{K}\ell(\theta;x_k)\Bigr)=\frac{1}{K}\sum_{k=1}^{K}\nabla_\theta\,\ell(\theta;x_k)
\]

把总共 \(K=mA\) 个样本（\(A\) 个 micro-batch，每个 \(m\) 个样本）拆开，各自算梯度再平均：

\[
\hat g=\frac{1}{A}\sum_{a=1}^{A}\underbrace{\Bigl(\frac{1}{m}\sum_{i=1}^{m}\nabla_\theta\ell(\theta;x_{a,i})\Bigr)}_{\text{第 }a\text{ 个 micro-batch 的梯度}}
=\frac{1}{mA}\sum_{a,i}\nabla_\theta\ell(\theta;x_{a,i})
\]

右端恰好就是把全部 \(mA\) 个样本当成一个大 batch 时的梯度。**所以两者在数学上完全相等，不是近似。**

这个等号依赖两个前提，缺一条就退化为近似：

1. **累积期间参数必须冻结**（不更新）。一旦中途更新，各个 micro-batch 的梯度就是在不同的参数点 \(\theta_a\) 上算出来的，右端不再是同一个 \(\theta\) 处的梯度——这正是"累积 \(A\) 步才更新一次"与"每步都更新"的本质差别——也提醒我们：accum 虽然等价，但不能用来在"每步更新"的研究设定下冒充大 batch 的结论。
2. **损失不能依赖 batch 统计量**。BatchNorm 的均值/方差、依赖 batch 的正则项都会让 \(\ell(\theta;x)\) 本身随分包方式改变，此时拆与不拆不再等价——这也是 Transformer 主流用 LayerNorm 而非 BatchNorm 的工程理由之一。

那么代价在哪？不在数学等价性，而在**算术强度**：拆成 \(A\) 份就要做 \(A\) 次前向+反向，多了 kernel 启动开销、少了大矩阵乘带来的访存合并收益 ⇒ 吞吐略降。**一句话：堆 accum 能救显存，救不了算力。**

#### 用方差量化 batch 的收益：为什么加 batch 有天花板

再看 batch 本身买到了什么。设单样本梯度 \(g_i\) 的均值是真梯度 \(\nabla f\)、单样本梯度噪声的总功率为 \(\sigma^2\)（协方差矩阵的迹）。对 \(B\) 个独立同分布样本取平均，由方差的运算性质 \(\operatorname{Var}\bigl(\frac1B\sum_i g_i\bigr)=\frac{1}{B^2}\sum_i\operatorname{Var}(g_i)\)：

\[
\hat g_B=\frac{1}{B}\sum_{i=1}^{B}g_i,\qquad
\operatorname{Var}(\hat g_B)=\frac{\sigma^{2}}{B}\quad\Longrightarrow\quad \text{标准差}\ \propto\frac{1}{\sqrt{B}}
\]

三条直接推论：

1. **降噪服从 \(1/\sqrt B\) 律**：要把梯度噪声的标准差砍一半，batch 得翻到 **4 倍**——收益迅速递减，很快就不划算。这是"batch 加到某个规模以后不值得再加"的最简账。
2. **信噪比随 \(B\) 线性增长**：\(\mathrm{SNR}=\frac{\lVert\nabla f\rVert^{2}}{\sigma^{2}/B}=\frac{B\,\lVert\nabla f\rVert^{2}}{\sigma^{2}}\)。远离最优点时 \(\lVert\nabla f\rVert\) 大，小 batch 也够；接近收敛时 \(\lVert\nabla f\rVert\to0\)，SNR 随之崩塌，这时才真正需要大 batch 压噪声——**这正是训练后期拉大 batch 的理论依据**，也是 2-4"临界 batch size"现象的由来：越过临界点后 \(\sigma^2/B\) 已远小于 \(\lVert\nabla f\rVert^2\)，继续加 batch 只买到更小的方差、买不到更快的收敛。
3. **与 5-0 的平台公式合起来**：把它代进上一篇推得的平台高度 \(f-f^{\ast}\approx\frac{L\sigma^{2}}{4\mu}\eta\)，得到 \(f-f^{\ast}\approx\frac{L\sigma^{2}}{4\mu}\cdot\frac{\eta}{B}\)。**衰减 \(\eta\) 与增大 \(B\) 在这个式子里地位完全对称**——往学习率上做文章还是往 batch 上做文章，本质是从同一个预算里出钱。之前这是两条经验，现在是一条公式的两边。

### 序列长度：被平方放大的显存与算力

序列长度 \(L\) 是三个量里"最贵"的，因为注意力的显存与算力都随它**超线性**增长：

- 注意力显存（KV cache 与中间矩阵）：\(\mathcal{O}(L^2)\) 每层（QKᵀ 相似度矩阵是 \(L\times L\)）；
- 注意力算力：\(\mathcal{O}(L^2 d)\)；
- 序列总长（token 数）对吞吐的影响：固定 batch 样本数时，\(N = \text{batch} \times L\) 个 token，而长序列让 micro-batch 上限**反比于 \(L\)**——你没法在同样显存里塞下 4K 序列的 4 个样本和 32K 序列的 4 个样本。

所以**序列长度与 micro-batch 是此消彼长**：显存预算固定时，\(\text{micro\_batch} \propto 1/L^2\)（注意力主导段）或 \(\propto 1/L\)（线性层主导段）。想用长上下文，就得砍 micro-batch，再用 accum 把有效 batch 补回来——但 accum 补的是优化动态，补不回"单步算力变贵"的事实。

### 三者联动的约束求解

真实配方是解一个带约束的账：给定

- 显存上限 \(M\) → 决定 \(\text{micro\_batch}_{\max}(L)\)
- 目标有效 batch \(B^*\)（由 2-4 临界 batch size 决定）与训练步数 \(T\)
- 卡数 \(P\)

目标是：在 \(B^*\) 不被违反的前提下，最大化吞吐（即最小化 accum，因为每多一次 accum 就多一次前向）。求法：

\[\text{accum} = \left\lceil \frac{B^*}{\text{micro\_batch}_{\max}(L) \times P} \right\rceil\]

若算出的 accum 过大（比如 > 64），说明单凭 DP 卡数撑不起目标 batch——要么加卡、要么接受低于临界 batch 的优化动态（此时应同步降低学习率，因为**有效 batch 决定了合适的学习率量级**，见 1-2/2-4 的线性缩放规则：batch 翻倍、学习率可翻倍）。

### 学习率随 batch 的线性缩放规则

一条被反复验证的实用法则（来自 Goyal 2017 训练 ResNet 与后续 LLM 实践）：**当有效 batch 乘以 \(k\)，学习率可乘以 \(k\)**，直到触及临界 batch size。这是因为大 batch 的梯度估计噪声更小，可以放心迈大步。

- 反过来说：用 accum 把有效 batch 从 32 撑到 256，学习率应从 \(1\times\) 提到约 \(4\times\)（在临界 batch 之内）；
- 但超过临界 batch 后再加 batch，噪声已近最优，**继续加学习率只会发散**——这正是 2-4 讲临界 batch size 的工程落点：**临界 batch 之上，加大 batch 必须同时衰减学习率**。

### 序列长度的"有效 token"陷阱

长序列不是免费午餐。一条 32K 的文档里如果只有前 2K 是有效内容，那么：

- 算力按 32K 全额计费（注意力是 \(L^2\)）；
- 但"有效信息密度"只有 2K/32K = 6%。

所以数据工程里要权衡：**是把 32K 文档塞满一个序列（贵、稀疏），还是切成多个 4K 短序列（便宜、但丢失跨段依赖）**。训练长上下文模型时常用"序列长度课程"——前期短序列高吞吐打基础，后期混入长序列学位置外推（3-5）。这也是 5-1 可视化要展示的：固定总 token 预算，不同 (micro-batch, 序列长度) 组合如何映射到吞吐与显存瓦片。

### 常见误区

- **误区一**："accum 和直接大 batch 完全等价"——**无条件地这么说才是误区**。准确的说法是：在"累积期间不更新参数"+"损失不依赖 batch 统计量"两个前提下，它确实是**精确等价**（微分算子线性，推导见上），不是"接近"。真正的差别在别处：accum 不改变峰值显存、却要多跑 \(A\) 次前向（吞吐下降）；一旦中途更新参数，或网络里有 BatchNorm 这类依赖 batch 统计量的层，等号立刻失效。
- **误区二**："batch 越大越稳、越好"——过临界 batch 后边际收益趋零、且需同步降学习率，盲目加 batch 是纯浪费算力。
- **误区三**："序列长度翻倍、显存也翻倍"——注意力段是**平方**关系，翻倍序列可能让显存翻 4 倍，远超线性直觉。

**参考答案：**
\(\text{batch}_{\text{eff}} = \text{micro\_batch} \times \text{grad\_accum} \times \text{data\_parallel}\)。梯度累积 = 把一次大 batch 的梯度平均拆成多次小 batch 前向再平均，优化动态接近；不同：accum 不改峰值显存但增加前向次数、吞吐略降，极端大 accum 时梯度二阶统计与大 batch 有微小差异。

\(\text{accum} = \lceil B^* / (\text{micro\_batch}_{\max}(L) \times P) \rceil\)。accum 过大（如 >64）说明单靠现有卡数和 micro-batch 撑不起目标有效 batch：要么加数据并行卡数，要么接受低于临界 batch 的优化动态（此时应同步降低学习率）。

**练习 4（对应退出标准 4）**

有效 batch 乘 \(k\)，学习率可乘 \(k\)（Goyal 2017 等），前提是未超过临界 batch size——因为大 batch 梯度噪声更小可迈大步。超过临界 batch 后噪声近最优，再加 batch 必须同步降学习率，否则发散。所以缩放规则的上界由 2-4 的临界 batch size 决定。

**参考答案：**

**练习 7（对应退出标准 7）**
(a) 用"梯度算子对求和线性"说明：为什么 \(\text{micro}=m\)、\(\text{accum}=A\) 时的累积梯度等于 \(mA\) 个大 batch 的梯度？写出推导并指出等号成立的两个前提。
(b) 设单样本梯度噪声功率为 \(\sigma^2\)，batch 为 \(B\)。写出平均梯度 \(\hat g_B\) 的方差，并说明"噪声标准差砍半需要 batch 翻几倍"。
(c) 写出信噪比 \(\mathrm{SNR}=\frac{B\lVert\nabla f\rVert^2}{\sigma^2}\)，据此解释为什么接近收敛时更需要大 batch，以及这与 2-4 临界 batch size 的关系。
(d) 把 (b) 的结论代入 5-0 的平台公式 \(f-f^*\approx\frac{L\sigma^2}{4\mu}\eta\)，说明"降 \(\eta\)"与"加 batch"为何是对称的两个旋钮。

%%%

**参考答案：**
(a) \(\nabla_\theta\bigl(\frac1K\sum_k\ell(\theta;x_k)\bigr)=\frac1K\sum_k\nabla_\theta\ell(\theta;x_k)\)（微分算子线性）。拆成 \(A\) 份各 \(m\) 个样本：\(\hat g=\frac1A\sum_{a=1}^A\frac1m\sum_{i=1}^m\nabla_\theta\ell(\theta;x_{a,i})=\frac{1}{mA}\sum_{a,i}\nabla_\theta\ell(\theta;x_{a,i})\)，正是 \(mA\) 个大 batch 的梯度 ⇒ 精确相等。前提：① 累积期间参数冻结（各 micro-batch 在同一点 \(\theta\) 求梯度）；② 损失不依赖 batch 统计量（无 BatchNorm 等）。
(b) \(\operatorname{Var}(\hat g_B)=\frac1{B^2}\sum_{i=1}^B\operatorname{Var}(g_i)=\frac{\sigma^2}{B}\)，标准差 \(\propto1/\sqrt B\) ⇒ 噪声标准差砍半需要 \(B\) 翻 **4 倍**（\(1/\sqrt B\) 律，收益迅速递减）。
(c) 接近收敛时 \(\lVert\nabla f\rVert\to0\)，SNR 随之崩塌，此时才需要靠大 batch 把 \(\sigma^2/B\) 压下去换取有效下降方向；而一旦 \(\sigma^2/B\ll\lVert\nabla f\rVert^2\)（越过 2-4 的临界 batch size），再加 batch 只继续缩小方差、不再加速收敛 ⇒ 收益封顶。
(d) 代入得 \(f-f^*\approx\frac{L\sigma^2}{4\mu}\cdot\frac{\eta}{B}\)：\(\eta\) 与 \(B\) 在式子里以乘积形式对称出现 ⇒ 想压低平台，衰减学习率与增大 batch 是可互换的两种出钱方式（实际常二者并发，见 5-0 的 "decay 段 batch 达峰 + LR 归零"）。
