## why

8-2~8-6 解决"一个训练任务怎么并行"，但集群上有**几十个任务在抢几百张卡**：谁先跑、谁让卡、碎片怎么留、坏了怎么恢复。调度层的三个经典故障——**占而不齐**（部分卡被占、任务起不来）、**碎片化**（总卡数够却找不到连续块）、**恢复税**（一次故障回滚 3 小时）——都不属于任何单元的模型代码，全在调度层。这一层做得差，8-0 辛苦攒的 MFU 会被集群利用率吃掉：**任务级 MFU 45% × 集群排队利用率 60% = 有效利用率 27%**。

## body

### 1 大规模训练任务的特殊性：全有或全无

DP/TP/PP 并行（8-2）意味着一个训练任务必须**同时占满它声明的全部卡**：TP 组差一张卡起不来，PP 流水缺一段就断。这与 web 服务"能起几个实例就起几个"完全不同，调度学术名 **gang scheduling**（成组调度）：要么全组资源一步到位，要么一个都不占。

反例（无 gang 的普通调度）会发生什么：任务要 64 卡，调度器先分配到 56 张，剩 8 张被别的任务零散占着 → 56 张**空转等 8 张**，占着茅坑 → 后续任务更难凑齐 → 死锁式雪崩。**所以大模型集群的调度器第一特性就是 all-or-nothing 的成组分配 + 队列**。

### 2 两套主流栈：Slurm 与 Kubernetes 的分工

| | Slurm（HPC 系） | Kubernetes + Volcano/scheduler-plugins（云原生系） |
|---|---|---|
| 分配模型 | 成组独占节点（partition+node 排他） | Pod 编排，Volcano 提供 gang 语义 |
| 拓扑感知 | 天然强（按机架/交换机组分配） | 需插件（binpack/拓扑约束） |
| 弹性 | 弱（作业固定规模为主） | 强（Pod 增删、抢占常态） |
| 训练生态 | torchrun/srun 直启 | 训练 operator（如 volcano job、kubeflow） |
| 2026 年实践 | 超算/自建大集群主流 | 云厂商与公司内部平台主流 |

**共同的核心机制**（无论哪套都要配）：
- **拓扑感知放置**：TP 组必须落在同机（NVLink 域），PP 邻段尽量同机架——8-3/8-4 的通信模型直接决定放置约束
- **bin-pack vs spread**：bin-pack（装箱紧凑）省整机、留大块；spread（打散）抗故障。**训练集群默认 bin-pack**，把碎片整理成大块
- **队列与公平**：多团队共享时按 dominant resource fairness（DRF）或配额分层；高优任务可抢占低优（低优任务要有 checkpoint 才配被抢占——§4）

### 3 碎片：一个装箱问题

集群 512 卡、碎片散在 16 台机器（每台剩 1~3 卡）。总空闲 32 卡，但一个 32 卡的新任务**一台也起不来**。这是经典装箱（bin packing）：把任务（体积=卡数）放进箱（节点组），目标最小化碎片。

**工程对策**（按效果排序）：
1. **预留整块**：调度器给"大任务队列"预留若干整机（如 10%），不接受小任务碎片化占用——牺牲一点利用率换大任务可起
2. **弹性填充**：大任务等块期间，允许小任务"临时填充"碎片，但**必须可抢占**（checkpoint 后让位）
3. **任务规格标准化**：申请卡数对齐机器粒度（8/16/64），从源头减少碎型请求

### 4 故障恢复：检查点间隔的优化公式

千卡集群的硬件故障率：设单卡/节点日故障率 \(\lambda_1\)，\(n\) 卡任务的整体故障率近似 \(\lambda = n\lambda_1\)（任一卡坏即任务暂停）。1024 卡、单卡 MTBF 10 万小时 ⇒ \(\lambda\approx1024/10^5\approx0.01\)/小时 ⇒ **平均 ~100 小时一炸**。加上网络/存储/软件故障，实际大训练**每周数损**是常态（5-2 的容错体系在此接上）。

恢复的代价模型（Daly 类一阶模型）：检查点耗时 \(C\)、故障率 \(\lambda\)、无故障时长 \(T\)，一个周期内期望浪费：

\[
W(\tau) \;\approx\; \frac{T}{\tau}\Bigl(\underbrace{C}_{\text{每次存档}}\Bigr) \;+\; \lambda T\Bigl(\underbrace{\frac{\tau}{2}}_{\text{平均丢失}}+\underbrace{R}_{\text{重启}}\Bigr)
\]

对 \(\tau\) 求导置零（\(\frac{dW}{d\tau}=0\)）得最优检查点间隔：

\[
\tau^{\ast} \;=\; \sqrt{\frac{2C}{\lambda}}
\]

**代数**：\(C=5\,\text{min}=300\,\text{s}\)（千卡 checkpoint 的真实量级）、\(\lambda=0.01/\text{h}=2.8\times10^{-6}/\text{s}\)：\(\tau^{\ast}=\sqrt{2\times300/2.8\times10^{-6}}\approx1.5\times10^{4}\,\text{s}\approx 25\,\text{min}\)。**直觉校验**：checkpoint 太频繁（τ≪τ*）——一直在写档；太稀（τ≫τ*）——每次故障丢半小时。**5-4 的"可复现性"（随机种子、数据顺序、优化器状态全量存档）决定 R 与"丢的可补性"，两单元合起来才是完整容错。**

### 5 弹性训练：换一种恢复哲学

传统方式：故障 → 全员停 → 从 checkpoint 重启到**原卡数**。弹性方式（torchrun elastic / 部分框架支持）： surviving 卡继续，world size 缩小，**不重启**。收益：省 R（重启+数据重载+重新预热，常 10~30 分钟）；代价：有效批大小变化（5-1 的耦合被破坏，需梯度累积补偿）、NCCL 重组、学习率语义漂移。**2026 年实践**：预训练主力任务多仍用"停-恢复"（简单可靠），弹性主要用于可中断的探针/消融任务与抢占式云竞价资源。

## ex

**练习 1（对应退出标准 1）**
解释 gang scheduling 的 all-or-nothing 语义为何是大规模训练的刚需：给出无 gang 调度下"56/64 卡"场景的恶化链条。

**参考答案：**
DP/TP/PP 要求全组同时在场（TP 差卡即无法组通信初始化）。无 gang：56 卡被占住空转 → 其余 8 卡被别的任务零散瓜分 → 本任务排队期间占着 56 卡不产出（利用率 0）→ 后续任务更难凑块 → 集群进入"高占用低产出"死锁。**gang + 队列把"占着等"改成"等着占"，空转成本转移为排队时延，集群吞吐才可预期。**

**练习 2（对应退出标准 2）**
集群 1024 卡分 128 机（每机 8 卡）。任务 A 要 96 卡（12 机）。说明拓扑感知放置的两条约束（TP 组同机、PP 邻段同机架）如何影响分配，并解释为什么"任意挑 12 台空机器"可能让 MFU 掉 10 个点。

**参考答案：**
TP 组（8 卡）必须整机（NVLink 域），所以分配单位是机而非卡；PP 邻段跨机时激活往返走 IB，8-3 练习 3 算过跨机激活流量。"任意 12 台"可能让 PP 邻段跨机架、DP 组跨交换机，通信时间拉长 → 8-0 拆解里的并行税变大，MFU 掉点。**放置是免费的优化：同样的卡，按拓扑放与乱放可差 5~15% 吞吐。**

**练习 3（对应退出标准 3）**
用 \(\tau^{\ast}=\sqrt{2C/\lambda}\) 核算：\(C=3\,\text{min}\)、512 卡、单节点日故障率 \(2\%\Rightarrow\lambda=512\times0.02/86400\approx1.2\times10^{-4}/\text{s}\)。求最优间隔；若 \(C\) 降到 1 min（增量 checkpoint、只存变化分片），\(\tau^{\ast}\) 变多少？说明为什么"降低 C"比"压 checkpoint 频率"更根本。

**参考答案：**
\(C=180\,\text{s}\)：\(\tau^{\ast}=\sqrt{2\times180/1.2\times10^{-4}}\approx1.7\times10^{3}\,\text{s}\approx 29\,\text{min}\)。\(C=60\,\text{s}\)：\(\tau^{\ast}\approx10^3\,\text{s}\approx17\,\text{min}\)。**\(\tau^{\ast}\propto\sqrt{C}\)**：降 C 让最优频率更高（丢得更少）且每次开销更小，浪费 \(W\propto\sqrt{2C\lambda}\) 双重下降。**压频率是二阶手段：C 不变时提频率会同时增加存档浪费，最优解只有一个点；降 C 才是移动整个曲线。**

**练习 4（对应退出标准 4）**
你的低优任务（消融实验）跑在高优集群上。解释"可抢占"为何必须以 checkpoint 为前提，并给被抢占时的标准动作序列。

**参考答案：**
抢占 = 随时可能被杀；无 checkpoint 则进度归零，低优任务的期望完成时间发散（每次快完成被杀最伤）。标准动作：① 收到 SIGTERM/驱逐信号 → 先存完整 checkpoint（含优化器、数据游标、RNG，5-4）；② 释放卡；③ 重新入队，恢复时校验数据版本与配置指纹。**设计含义：可抢占队列里的任务必须把"启动到首个 checkpoint"的冷启动成本压到最低（如首个 checkpoint 只存 15 分钟）。**

**练习 5（对应退出标准 5）**
弹性训练在故障后 world size 从 64 缩到 60。列三个必须处理的连带问题，并说明各自的一阶对策。

**参考答案：**
① 有效批变化：DP=60 vs 64，\(B=\text{micro}\times\text{accum}\times\text{DP}\) 变小 ⇒ 梯度累积 +1/15 补偿，或按 2-4 的临界 batch 论证"变化在小侧可忽略"；② 梯度同步语义：DP 组重组，NCCL 需重建通信域（新一轮 init，非零成本）；③ 学习率与 warmup 语义：若按步数调度，缩容后吞吐略降、每步样本略少，loss 曲线不可比 ⇒ 记录 world size 变更事件、必要时按 token 数重标定。**结论：弹性不是免费的，"省一次重启"要和三个连带成本对账。**

**练习 6（对应退出标准 6）**
集群月度报告：任务级平均 MFU 47%，集群空闲率 22%，抢占导致的重复计算占 6%。算"有效算力利用率"，并指出三个数字里哪个最值得先攻。

**参考答案：**
有效利用率 \(=0.47\times(1-0.22)\times(1-0.06)\approx34\%\)。**空闲率 22% 最值得先攻**：它通常是排队/碎片问题，用 gang+预留+填充可压到 10% 以内（×1.15 收益），工程难度低于 MFU（要动内核与并行）与抢占（要动 checkpoint 体系）。**方法论：利用率是乘积链，先修最薄弱因子。**
