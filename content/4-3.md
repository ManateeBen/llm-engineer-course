## why

预训练给了模型"世界知识"，SFT（监督微调）教它"怎么听话"。这道工序的数据有个反直觉的特点：**数量与质量严重倒挂**——LIMA 用 1000 条人工精选数据微调的模型，在大量人类盲测中接近用 5 万条 Alpaca 数据微调的水平；DEITA 进一步证明，几千条经复杂度/质量双筛的数据可以超过十万条随机数据。

更麻烦的是 SFT 数据自己的三个坑：**模板痕迹**（Alpaca 用 175 个模板生成全部数据，模型学会的是模板不是任务）、**任务覆盖偏科**（开放式问答扎堆、复杂推理稀缺）、**长序列浪费**（短样本 padding 到统一长度，一半算力在算填充符）。本单元把 SFT 数据工程拆成四件事：**构造来源、质量过滤、多样性覆盖、训练侧打包**，每一件都给可操作的判据。

## body

### SFT 数据长什么样

一条 SFT 样本 = 一个多轮对话序列，token 分两类：**prompt**（用户/系统的话，不贡献 loss）与 **response**（助手的话，贡献 loss）。微调目标就是最大化 response 部分的对数似然（1-1 的交叉熵，只在 response token 上求和）。

这个结构带来第一个工程细节：**loss mask**。填充符（PAD）与 prompt 的 loss 必须屏蔽，否则模型会把"填充"和"重复用户问题"也当学习目标——这是新手最常见的 bug 之一，症状是模型学会在回答末尾复读 prompt 或不停吐 PAD。另一个细节是 **EOS 的处理**：response 结束不加 EOS，模型就学不会"什么时候闭嘴"，表现为停不下来。

### 数据从哪来：四条路线

1. **人工撰写**：质量天花板，成本也天花板（LIMA 的 1000 条是社区精修产物）；
2. **强模型生成 + 人工筛**：主流性价比路线（Self-Instruct 管线见 4-2）；
3. **真实业务数据**：客服日志、论坛问答——最贴近部署分布，但要过脱敏与去重（4-0）；
4. **任务专精数据**：从 benchmark 的 train split 反向构造（数学题带步骤、代码带测试）。

不论哪条路线，都要过同一套筛子。

### 质量过滤：复杂度 × 质量双轴

DEITA（Liu 2024）的核心发现：**好数据 = 足够复杂（学到东西）× 回答得好（信号干净）**。它用两个打分器：

- **复杂度打分**：用 ChatGPT 评估指令的推理深度、约束数量、步骤数——太简单的指令（"翻译这句话"）模型早会了，学了白学；
- **质量打分**：评估回答的正确性、完整性、有害性——回答错的样本是负资产，比没有还糟。

双轴各切一刀，几千条双高样本就能打赢十万条随机数据。IFD（Li 2023）换个更便宜的思路：**用模型自己给指令打分**——指令的条件困惑度（给定指令后生成该回答的难度）作为"这条数据能教我多少"的代理指标，按分数取头部。两者共同指向一个原则：**SFT 数据是筛出来的，不是攒出来的**。

还有几条血泪规则：

- **去重必须做**：SFT 集里的近重样本会让模型过拟合到高频任务（2-2 的过拟合在数据侧的镜像），4-0 的段落级去重同样适用；
- **格式一致性**：对话模板、角色 token、EOS 全库统一，混用模板等于让模型学"什么时候用哪种壳"这种无解任务；
- **错误样本一票否决**：宁可留空，不要错答——模型的置信度会被错例带歪。

### 多样性覆盖：给数据画地图

质量筛完，第二件事是**覆盖**。做法是把每条指令打到几个维度上：任务类型（问答/摘要/代码/推理/创作……）、领域（百科/医疗/法律……）、长度、难度、语言。然后看分布的空洞：Alpaca 式生成的典型病是**短指令、单轮、指令模板单一**——模型在分布外的真实请求上立刻露馅。

判断"覆盖够不够"的三个指标：

1. **任务-领域联合熵**：联合分布越均匀，模型行为越可预期；
2. **模板去重后的指令模式数**：如果 80% 数据落在 20 个句式模板里，多样性是假的；
3. **分布外探针**：留一小批与训练集刻意不同的请求，微调后专门测它们——过拟合的模型在探针上断崖式下跌（2-2 的偏差-方差视角）。

难度也要配比：**太易的数据浪费容量，太难的数据（超出模型能力的多步推理）产生幻觉式回答**——苏格拉底式"跳一跳够得着"的中等难度数据密度最高，这也是 Evol-Instruct 式难度演化在 SFT 侧的价值（4-2）。

### 序列打包：把算力花在内容上

SFT 样本长短悬殊（10 token 的"好的"到 8000 token 的代码解释）。传统做法 padding 到统一长度：**短样本的算力全耗在填充符上**，长样本又被截断。**序列打包（packing）**把多条短样本首尾相接塞进一个训练序列，配上**位置 id 重置**与**注意力隔离**，让一条长序列装多个独立文档——显存与算力都花在真实 token 上。

关键在注意力隔离：如果打包后不做 mask，序列前部的文档会"看到"后部文档，模型学到跨样本的幻觉关联（前一个问题的答案串到下一个问题上）。两种做法：**块对角 mask**（每条样本一个独立注意力块，最干净，LongAlign 采用）或**文档级位置 id 重置 + 因果 mask 内不跨文档**。看交互图：左边是朴素打包的注意力矩阵（彩色块渗出文档边界），右边是隔离后的块对角结构，以及 loss 只在 response token 上点亮：

### 判断框架

审计一批 SFT 数据，按清单过：

1. **格式**：模板统一吗？EOS 齐吗？loss mask 只覆盖 response 吗？
2. **质量**：双轴（复杂度 × 质量）打过分的样本占比？错例一票否决执行了吗？
3. **多样**：任务×领域×长度分布有空洞吗？指令模板浓度多高？分布外探针的成绩曲线健康吗（2-2）？
4. **干净**：近重去重做过吗（4-0）？PII 脱敏、有害内容过滤过关吗？
5. **效率**：packing + 注意力隔离上了吗？长样本截断策略是什么？

## ex

**练习 1（对应退出标准 1）**
SFT 的 loss 为什么必须只算在 response token 上？漏掉 EOS 训练会导致什么现象？

%%%

**参考答案：**
SFT 目标是学"给定请求如何回答"，prompt 是条件不是目标；把 prompt 也算进 loss 会让模型去拟合用户问题本身（复读、过度模仿提问风格）。PAD 若不屏蔽，模型还会学吐填充符。漏掉 EOS：response 结束没有终止信号，模型学不会"何时停止"，典型症状是回答停不下来、在结尾处复读或无限延伸。

**练习 2（对应退出标准 2）**
列出 SFT 数据的四条来源路线及各自的主要风险。

%%%

**参考答案：**
① 人工撰写：质量最高，成本与规模受限（千人级已是极限）；② 强模型生成+人工筛：性价比主流，风险是继承教师分布与错误（4-2 的上限问题），必须配质量过滤；③ 真实业务数据：最贴近部署，风险是 PII/敏感信息与脏数据，须脱敏+去重；④ 任务专精数据（benchmark 反构）：针对性强，风险是过拟合 benchmark 的分布（评测污染，7-1）。

**练习 3（对应退出标准 3）**
DEITA 的双轴筛选是什么？为什么"错例一票否决"？

%%%

**参考答案：**
双轴：复杂度打分（指令的推理深度/约束数/步骤数——太易白学）× 质量打分（回答的正确性/完整性/无害性——错答是负资产），各切一刀取双高。错例一票否决：模型对训练信号的信任是全局的，错答会以高置信度污染参数（错误模式被强化），且诱导模型在相似问题上幻觉；一条错例的负收益常大于十条平庸样本的正收益。

**练习 4（对应退出标准 4）**
Alpaca 式生成数据的典型多样性病是什么？用哪三个指标诊断？

%%%

**参考答案：**
病：短指令、单轮、175 个模板生成全部数据——模型学到的是模板与表层格式，分布外真实请求上露馅。诊断指标：① 任务×领域×长度联合熵（越均匀越可预期）；② 模板去重后的指令模式数（80% 数据集中在 20 个句式 = 假多样性）；③ 分布外探针成绩曲线（过拟合模型在探针上断崖下跌）。

**练习 5（对应退出标准 5）**
序列打包为什么必须配注意力隔离？不隔离会学到什么？

%%%

**参考答案：**
打包把多条样本首尾相接进同一序列以省 padding 算力。若不隔离（只用因果 mask），前部样本的 token 会看到后部样本的内容，模型把"前一个问题的背景"误当作当前问题的条件——学到跨样本幻觉关联（答案串题、上下文泄漏）。隔离（块对角 mask 或文档级位置重置）保证每条样本是一个独立世界；LongAlign 在长上下文对齐中采用块对角 mask，同时 position id 按文档重置， RoPE 的相对位置才不跨文档错乱。

**练习 6（对应退出标准 6）**
给出审计一批 SFT 数据的五项清单。

%%%

**参考答案：**
① 格式：模板统一、EOS 齐全、loss mask 只覆盖 response；② 质量：复杂度×质量双轴打分、错例一票否决；③ 多样：任务×领域×长度分布无大空洞、指令模板浓度低、分布外探针健康；④ 干净：段落级近重去重（4-0）、PII 脱敏、有害过滤；⑤ 效率：packing+注意力隔离落地、长样本截断策略明确。
