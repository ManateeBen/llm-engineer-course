## why

6-5 讲的是"安全"的技术面；本单元讲它在国内语境下的**制度面**——这不是附加题，是上线前置条件。对 SRE 出身的人，本章恰好是主场：合规要求全部可以翻译成 pipeline 上的卡点、CI 里的检查、监控里的告警。核心视角：**把备案从"提交一堆文档"变成"一套可复现、可审计的工程流水线"**——语料 license 扫描、模型卡生成、评估报告版本化、发布门禁。谁的这套东西自动化程度高，谁就能在合规成本上甩开同行。

## body

### 1 法规框架：三层结构（事实性梳理）

国内生成式 AI 的监管是三层叠加（本节为公开规章的事实性梳理，具体执行以主管部门最新解释为准）：

| 层 | 规范 | 对工程的含义 |
|---|---|---|
| **基础法律** | 《网络安全法》《数据安全法》《个人信息保护法》 | 训练数据来源合法、个人信息合规（PII 过滤）、日志留存 |
| **专门规章** | 《生成式人工智能服务管理暂行办法》（2023-08-15 施行） | 面向公众提供生成服务：安全评估、内容安全、标注规则、投诉处置 |
| **配套标准** | TC260《安全基本要求》（2024）、《语料来源安全指南》、标识办法（2025-09-01 施行） | 把法规翻译成可执行的技术检查项与报告模板 |

**适用范围的红线**：向**境内公众**提供生成式 AI 服务才触发备案义务；纯自用/研发、未向公众开放的不触发（但数据合规义务仍在）。B2B/API 服务同样在监管范围内。

### 2 备案与安全评估：把"交材料"拆成 pipeline

大模型备案（属地网信办）要交的核心材料，逐项对应到工程产物：

\[
\text{备案材料} \;=\; \underbrace{\text{安全评估报告}}_{\text{评估 harness + 结果（7-0/6-5 口径）}} \;+\; \underbrace{\text{模型卡片}}_{\text{版本化元数据}} \;+\; \underbrace{\text{语料说明}}_{\text{来源清单 + license 扫描}} \;+\; \underbrace{\text{标注规则}}_{\text{标注指南 + 抽检记录}} \;+\; \text{处置机制}
\tag{6.7.1}
\]

**流水线化的关键设计**：

- **评估 harness 复用**：安全评估报告要的"拒答测试、拒答误伤测试、生成内容抽检"直接复用 6-5 §5 的评测集——**不要为备案单独造一套评测**，两套口径必然漂移；
- **语料 license 扫描**：CI 里跑 license 兼容性矩阵（开源语料的 license、 robots.txt 抓取合规、PII 检测），输出机器可读的来源清单——这是"语料说明"的自动生成源；
- **模型卡（model card）版本化**：每次训练/对齐跑完，把数据配方（阶段 4 的配比）、评测分（7-2 显著性口径）、安全指标（6-5 的 ASR/过度拒绝）自动汇成一张带 commit hash 的卡——**备案材料 = 一次 CI 运行的产物，而不是项目结束时的考古**；
- **发布门禁**：未通过安全评估（ASR 或过度拒绝超阈值）的模型不允许进生产 registry——和 5-4 的实验管理接起来。

### 3 内容安全双轨：输入侧与输出侧

训练层（6-0/6-5 的拒答训练）之外，服务侧的两道过滤（国内实务的标配，双轨都要）：

- **输入侧**：prompt 预筛——敏感词/正则快筛 + 分类器（涉政、暴恐、色情、歧视等类别），命中直接拒答或转人工；同时是 prompt 注入检测（10-1 的 agent 语境的输入面）；
- **输出侧**：生成内容过滤——流式场景下"边生成边过滤"（延迟敏感）或"生成后过滤"（质量敏感）；分类器独立于被服务模型（6-5 的系统层逻辑——**别用被保护的模型守自己**）。

**过滤的三难**：误伤率（正常请求被拦）、漏过率（违规内容放行）、延迟（过滤加在关键路径上）。解法是分层：快筛（μs 级）拦确定性违规，分类器（ms 级）兜模糊样本，人工抽检兜长尾——**每层误判回流成下一层的训练数据**，这是持续改进的闭环。

### 4 标识义务与日志留痕

2025-09-01 施行的《人工智能生成合成内容标识办法》要求：

- **显式标识**：AI 生成内容在用户界面层明确标注（文字提示/水印），平台侧可检测；
- **隐式标识**：元数据里嵌入生成来源信息（文件元数据、不可见水印）——工程上是内容管线的附加步骤；
- **对基础设施的含义**：多模态内容管线（9-3/9-4）要在生成出口统一挂标识；日志里记录"是否 AI 生成 + 标识状态"供监管检查。

日志侧（规章 + 实践）：输入输出留存（实务中常见 6 个月以上口径，以最新要求为准）、处置记录、投诉闭环时限——**SRE 把这条做成日志分级 + 保留策略 + 审计查询**，和 5-4 的实验日志、6-7 的评估报告共用一个可观测栈。

### 5 SRE 视角：合规即 CI

把上面所有东西压成一张发布检查单（每项都有自动化 owner）：

| 卡点 | 自动化形态 | 失败动作 |
|---|---|---|
| 语料 license/PII | CI 扫描脚本 | 阻断训练任务启动 |
| 模型卡完整性 | CI 生成 + schema 校验 | 缺字段不允许进 registry |
| 安全评估（ASR/过度拒绝/拒答正确率） | 评测 harness 跑批 | 超阈值阻断发布 |
| 输出过滤误伤率 | 流量回放 + 人工抽检流水线 | 超阈值回滚配置 |
| 标识与日志留存 | 服务自检 + 日志策略检查 | 上线前自检不过不上线 |
| 投诉处置 SLA | 工单系统 + 告警 | 超时升级 |

**这张表的深层价值**：备案材料、事故响应、审计检查三个场景共用同一套自动化产物——**合规的边际成本趋近于零**，而每次"为备案临时补材料"的团队，边际成本线性累积。

## ex

**练习 1（对应退出标准 1）**
列举大模型备案的五个核心材料项，并说明每项由哪条工程流水线自动产出。

**参考答案：**
① 安全评估报告 ← 评测 harness（6-5 §5 的 ASR/过度拒绝/拒答集，7-2 的显著性口径）；② 模型卡片 ← 训练/对齐流水线的元数据汇总（数据配方 + 评测分 + 安全指标 + commit hash）；③ 语料说明 ← 语料入库 CI 的 license/PII 扫描结果（机器可读来源清单）；④ 标注规则 ← 标注指南文档 + 抽检一致率记录（4-3/4-4 的质量控制产物）；⑤ 处置机制 ← 内容过滤监控 + 投诉工单系统的配置与 SLA 记录。**每项都有"现成的工程产物"可复用——备案是流水线的汇报，不是额外项目。**

**练习 2（对应退出标准 2）**
语料来源合规：给五类常见语料各定一个风险级（绿/黄/红）与处置动作。

**参考答案：**
① 明确宽松 license 的开源数据集（Apache/MIT/CC-BY）→ 绿：登记入清单即可；② 研究用途开源数据（如某些 CC-BY-NC 数据集）→ 黄：法律评估 + 限制使用范围记录；③ 爬虫抓取的公开网页 → 黄：robots.txt 合规检查、PII 过滤、频率限制，保留抓取日志；④ 用户生成内容（UGC）→ 黄/红：授权链路审查（用户协议覆盖商用+训练）、隐私字段脱敏；⑤ 来源不明/盗版内容 → 红：禁止入训练集，CI 直接拦。**判据不是"能不能拿到"而是"授权链路是否覆盖商用训练 + 隐私字段是否已脱敏"——两问有一问不过就升级风险级。**

**练习 3（对应退出标准 3）**
输出过滤的"三难"（误伤/漏过/延迟）：设计一个三层过滤架构，给出各层的延迟预算与误判数据如何闭环。

**参考答案：**
三层：① 快筛层（敏感词+正则，μs 级，预算 <1 ms）：拦确定性违规，误判回流成词表修正；② 分类器层（小模型安全分类，ms 级，预算 5~20 ms，可流式分段）：兜模糊样本，误判（过杀/漏放）抽检回流成分类器的 hard negatives 重训；③ 人工抽检层（按流量 0.1%~1% 抽样）：兜长尾 + 校准前两层阈值，产出月度质量报告。闭环：每层误判样本带上下文进同一数据湖，回流训练用——**三层不是静态管道，是同一数据闭环的三个采样率**。延迟超预算时的降级策略（保延迟丢过滤质量 vs 保质量丢部分流量）按业务风险等级预配置。

**练习 4（对应退出标准 4）**
《标识办法》对一条"AI 生图 → 用户编辑 → 转发"的内容链路意味着什么？指出显式/隐式标识各自的责任点。

**参考答案：**
显式标识：生成侧在输出界面标注"AI 生成"（平台展示层），用户编辑后转发时平台仍应保留/重新提示生成来源（传播链的持续提示义务）；隐式标识：生成侧在文件元数据/水印里写入来源信息，**用户编辑通常不抹除元数据水印**——接收方平台可用它检测（这是隐式标识的设计意图：元数据级可追溯）。责任点：生成服务提供者负主责（生成即标），传播平台负检测与提示义务（元数据检测 + 人工复核疑似 AI 内容）。工程含义：多模态管线（9-4）的出口必须统一挂双标识，转发链路做元数据透传——**标识不是 UI 文案，是内容对象上的持久属性。**

**练习 5（对应退出标准 5）**
设计发布门禁：一个模型更新要上生产，列出六个自动化卡点及各自的阻断/告警级别。

**参考答案：**
（按"硬阻断→告警"分级）① 语料 license/PII 扫描不过 → **阻断**（合规红线）；② 模型卡缺字段/与训练记录不符 → 阻断；③ 安全评估 ASR 超基线+1 个点或过度拒绝率 >5% → 阻断（6-5 的验收线）；④ 能力回归：核心 benchmark 掉 >2%（7-2 显著）→ 阻断或升级人工裁决；⑤ 过滤配置误伤率回放超阈值 → 告警 + 灰度观察；⑥ 标识/日志自检不过 → 阻断（服务级合规）。**分级原则：合规红线（内容/数据/标识）一律硬阻断；质量类（能力/误伤）可灰度+人工，但超限即阻断。门禁的权威性来自"没有绕过通道"——所有例外走人工审批并留痕。**

**练习 6（对应退出标准 6）**
某团队备案材料是"上线前两周集中补"：语料清单靠人工回忆、安全报告临时跑评测、模型卡手写。列出这种模式的四个具体风险，并给出流水线化的最小改造。

**参考答案：**
风险：① 语料清单人工回忆 ⇒ 漏登记 ⇒ 备案信息不实（法律风险）+ 无法复现训练；② 安全报告临时跑 ⇒ 口径与线上不一致（线上过滤配置与报告版本不符）⇒ 评估失真；③ 模型卡手写 ⇒ 与实际训练配置漂移（换了数据配方没更新）⇒ 审计对不上；④ 每次从零补 ⇒ 边际成本线性累积，且每次都可能引入新错误。最小改造：a) 语料入库 CI 化（登记即扫描，清单从 DB 导出）；b) 评测 harness 复用线上同版本（安全评估 = CI 里的一个 job）；c) 模型卡由训练流水线自动生成（schema 校验进 registry 门禁）；d) 备案材料打包成一个 script（一键导出全部产物 + 版本戳）。**核心：备案材料必须是 CI 的副产物，而不是并行维护的第二数据源——两处维护必漂移。**
