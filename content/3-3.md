## why

1-0 讲过 MHA（Multi-Head Attention）的原理：\(h\) 个头，每个头有自己的 Q/K/V 投影。当时把多头当作"表示多样性"的免费午餐——训练时确实如此。但**推理时多头是显存杀手**：每生成一个 token，都要把全部层的 K、V 缓存下来（KV cache），长上下文下 KV cache 能占到模型参数的十几倍。本单元讲工业界为治这个病演化出的三种改法：MQA（所有头共享一份 KV）、GQA（分组共享）、MLA（低秩压缩 KV）。读完你能算一个模型在给定上下文长度下的 KV cache 显存，能说出"为什么 LLaMA-2 70B 用 GQA、DeepSeek-V2 用 MLA"这种工程决策背后的账。

## body

### 先把病立起来：KV cache 的账

Decoder 推理是自回归的：生成第 \(t\) 个 token 时，需要全部历史 token 的 K、V。朴素的实现每步重算全序列（浪费），工程实践是**缓存**：每层的每个头存一份 K、V，随生成增长。

以一个 7B 模型（\(L=32, d=4096, h=32\)）为例，batch=1、上下文 8k：

\[
\text{KV cache} = 2\times L\times n\times d\times\text{bytes} = 2\times32\times8192\times4096\times2\text{（BF16）} \approx 4.3\ \text{GB}
\]

对照：模型权重本身约 14 GB（7B×2 字节）。**KV cache 已经达到权重的 1/3**，且随上下文线性增长——32k 上下文就是 17 GB，128k 就是 69 GB，比权重还大。更糟的是 batch：KV cache 按 batch 倍增，而推理服务必须靠 batch 摊薄成本——batch=32 时 KV cache 185 GB，一张 80 GB 的 A100 直接爆。Pope 等人 2022 年的分析结论：**长上下文推理是显存带宽问题，不是算力问题**——每步只算一个 token 的矩阵向量乘，算力闲着，显存忙着搬 KV。

病立起来了，三种药方分别从"减少份数"和"压缩每份"两个方向下手。

### MQA：所有头共享一份 KV

MQA（Multi-Query Attention，Shazeer 2019）最激进：Q 仍然 \(h\) 份（每头一个查询），但 K、V 全部头共享**同一份**：

\[
\text{注意力}_i = \text{softmax}\!\left(\frac{Q_i K^\top}{\sqrt{d/h}}\right)V,\quad i=1,\dots,h
\]

效果立竿见影：KV cache 从 \(2\times L\times n\times h\times d/h=2Lnd\) 降到 \(2\times L\times n\times d/h\)——**除以头数**。上例中 KV cache 从 4.3 GB 降到 0.14 GB，batch=32 也能塞进 5 GB。代价：表示多样性被砍掉一大半——所有头必须共用同一组 K/V，实证质量有可见下降（尤其小模型）。Shazeer 原论文的结论是"质量损失可控、速度收益巨大"，PaLM、Gemini、LLaMA-2 70B 都采用了它。

### GQA：分组共享的折中

GQA（Grouped-Query Attention，Ainslie et al. 2023）是 MHA 与 MQA 的连续插值：把 \(h\) 个 Query 头分成 \(g\) 组，**每组共享一份 KV**：

- \(g=h\)：就是 MHA（每头独立 KV）；
- \(g=1\)：就是 MQA（全部共享）；
- 实践中 \(g=8\)（如 32 头分 8 组）几乎追平 MHA 质量，KV cache 只有 MHA 的 \(8/32=1/4\)。

GQA 的杀手锏是**可以从已有 MHA checkpoint 升级**：对同组内各头的 K/V 投影矩阵取平均，得到一个 GQA 模型，再花约 5% 的原始训练算力微调回血——等于给存量 MHA 模型的"推理加速改造包"。LLaMA-2/3 的 70B 用的是 \(g=8\)；Mistral、Qwen 等主流开源模型普遍跟进。**今天要做新模型，默认答案就是 GQA。**

### MLA：低秩联合压缩

MLA（Multi-head Latent Attention，DeepSeek-V2 2024）走另一条路：不减少份数，而是**压缩每份的维度**。核心是一个低秩联合投影——把 K、V 联合压到一个小的潜在向量 \(c\)（维度远小于 \(d\)），推理时缓存的是这个压缩后的 \(c\) 而不是完整的 K/V：

\[
c_{t} = W^{DKV} x_t \in \mathbb{R}^{d_c},\quad d_c \ll d
\]

DeepSeek-V2 的实际配置：KV cache 降到 GQA 同级的 1/3 以下，同时**质量不降反升**（比同规模 MHA 基线略优）——因为低秩投影相当于给注意力加了一个正则，且压缩-重建是端到端训练出来的，不是事后有损压缩。代价：注意力部分的实现复杂度显著上升（投影/重建矩阵、与 RoPE 的交互都要重新设计），工程门槛高。

### 三种变体对照表

| 维度 | MHA | MQA | GQA | MLA |
|---|---|---|---|---|
| KV 份数 | \(h\) | 1 | \(g\)（通常 8） | 1（但低秩） |
| KV cache 相对 MHA | 1× | \(1/h\) | \(g/h\) | \(\approx 1/(h\cdot k)\) |
| 质量（同规模） | 基线 | 可见下降 | 几乎持平 | 持平或略升 |
| 实现难度 | 低 | 低 | 低 | 高 |
| 代表采用 | 早期模型 | PaLM/Gemini | LLaMA-2/3 70B、Mistral | DeepSeek-V2/V3 |

### 判断框架：什么时候用什么

1. **从零训练**：GQA（\(g=8\) 左右）是默认答案——质量几乎免费，推理省 4~8 倍 KV。
2. **改造存量 MHA**：GQA 的"平均 KV 投影 + 少量微调"路径，成本最低。
3. **极限省显存且愿意付工程成本**：MLA——DeepSeek 用它把 236B 总参数的模型做到单卡可推理的部署经济性。
4. **绝对不要**：无脑 MQA 到小模型上——质量损失在小模型上被放大。

注意 KV cache 优化还有一条独立战线是**系统层**：vLLM 的 PagedAttention 把 KV cache 像虚拟内存一样分页管理，消除显存碎片、支持共享前缀（系统提示只存一份）——Kwon et al. 2023。它与注意力变体正交，两个战线要一起吃。

## ex

**练习 1（对应退出标准 1）**
写出 KV cache 大小公式，并计算 \(L=32,d=4096,h=32,n=8192\)、BF16 下的字节数。

%%%

**参考答案：**
KV cache \(=2\times L\times n\times d\times\text{bytes}\)（MHA）。代入：\(2\times32\times8192\times4096\times2=4{,}294{,}967{,}296\) 字节 ≈ 4.3 GB（MiB 口径 4096 MiB）。

**练习 2（对应退出标准 2）**
MQA 为什么省显存？把上面的例子按 MQA 重算。

%%%

**参考答案：**
MQA 所有头共享一份 K/V，KV cache 从 \(2Lnd\) 降为 \(2Lnd/h\)（Q 不占 cache）。代入：\(2\times32\times8192\times4096\times2/32\approx0.134\) GB ≈ 134 MB，约为 MHA 的 1/32。

**练习 3（对应退出标准 3）**
GQA 为什么被称为"MHA 与 MQA 的连续插值"？它的"从 MHA 升级"路径具体怎么操作？

%%%

**参考答案：**
GQA 的组数 \(g\) 是连续旋钮：\(g=h\) 退化为 MHA，\(g=1\) 退化为 MQA，中间任意分组。升级路径：取已有 MHA 模型同组内各头的 K/V 投影矩阵做平均，得到 GQA 初始化，再用约 5% 原始算力微调——等于给存量模型的推理加速改造包。

**练习 4（对应退出标准 4）**
MLA 与 GQA 省显存的机制有何本质不同？为什么 MLA 能做到"省显存还不掉质量"？

%%%

**参考答案：**
GQA 减少 KV 的份数（结构共享），MLA 压缩每份的维度（低秩联合投影，缓存潜在向量）。MLA 不掉质量因为压缩-重建矩阵是端到端训练出来的（软降维、表示被重新组织），而非事后有损压缩；低秩还自带正则效果，DeepSeek-V2 上甚至略优于同规模 MHA。

**练习 5（对应退出标准 5）**
一个部署团队要把 70B 模型的并发从 batch=4 提到 batch=32，显存不够。按本单元框架给出两条独立战线的建议。

%%%

**参考答案：**
模型侧：换 GQA（\(g=8\)）或 MLA，KV cache 降 4~8 倍（LLaMA-2 70B 本就是 GQA）；系统侧：上 vLLM/PagedAttention 分页管理 KV，消碎片、共享系统提示前缀，等效再榨出数倍并发。两条战线正交，应同时做；另外可叠加 KV cache 量化（INT8/FP8）进一步压缩。
