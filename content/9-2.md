## why

9-0 给了零件清单（编码器/投影器/LLM），本单元讲**怎么组装成一性能良好的 VLM**。主流架构只有三种：桥接式（LLaVA：投影器拼接）、查询式（BLIP-2：Q-Former 压缩）、注入式（CogVLM/Flamingo：视觉注意力插进 LLM 每层）。三种架构的显存账、训练成本、能力上限都不同。另外两个工程关键：**动态分辨率**（anyres 切图，省 token 保细节）与**多模态指令数据构造**（怎么用 LLM 造训练数据）。这是你能复现一个 VLM 的全部架构知识。

## body

### 1. 三种组装范式的账本对比

**桥接式（LLaVA 家族）**：

\[
H = \big[\, \phi(f_I(I)) \,;\, \mathrm{Emb}(T)\,\big] \to \mathrm{LLM}
\]

视觉特征投影后直接拼在文本 embedding 前。显存增量 = 视觉 token 的激活（8-6 的 \(34sbhL\) 账上再加 \(N_{\text{vis}}\) 个位置的序列维）。训练便宜（投影层 + LoRA 或全参）。

**查询式（BLIP-2/Qwen-VL adapter）**：Q-Former 用 \(N_q\) 个可学习 query（典型 32）对视觉特征做交叉注意力，输出固定长度 32 token 不管原图多大——**视觉 token 数恒定 ⇒ 算力可预测**，代价是 32 个 query 的信息瓶颈。

**注入式（CogVLM/Flamingo）**：在 LLM 每层加一个视觉专家模块（对视觉特征做 cross-attention），视觉信息在每一层都可访问。具体效果与开销依赖数据、层数和实现，不存在通用能力排序。Flamingo 的交叉注意力与 CogVLM 的视觉专家并非同一结构。

| 范式 | 视觉 token 数 | 显存开销 | 能力上限 | 代表 |
|---|---|---|---|---|
| 桥接 | \(N_{\text{vis}}\)（576~2.8K） | 中 | 高 | LLaVA-1.5 |
| 查询 | 固定 32~256 | 低 | 中 | BLIP-2 |
| 交叉注意力 | 视觉表示另存，语言序列可不增加 | 依实现 | 需实测 | Flamingo |

### 2. 动态分辨率：anyres 的切图经济学

固定 336×336 输入对高分辨率文档/图表是灾难（文字糊掉）。anyres 方案：

1. 原图按长宽比缩放到网格（如最多 4×4 格，每格 336×336）
2. 全局缩略图（336）+ 局部格子图各过编码器
3. token 数 = \((n_g+1)\times 576\)，\(n_g\le 16\) ⇒ 最多 9792 视觉 token

**经济学**：文档理解场景下，anyres 把准确率从 51% 提到 67%（Qwen-VL 数据）；但 token 预算爆炸——\(4\times4\) 格时单图近 10K token，注意力 FLOPs 按 8-6 的账线性增序列长、平方增注意力。**工程约束**：上下文窗口 + KV 显存（8-7 的账）决定任何res 配置的上限——10K 视觉 token × BF16 KV，7B 模型 32 层 ≈ \(2\times32\times3584\times10\text{K}\times2\text{B}\approx 4.6\) GB/图，**多图会话迅速吃掉显存**。

### 3. 多模态指令数据：构造与质量

LLaVA 的核心发现：**用 GPT-4 把 COCO 的 caption 扩成对话**（bounding box/QA/详细描述三种指令），15 万条即可激发对话能力。后续工作的质量结论：

- **多样性 > 数量**：覆盖任务类型（OCR/图表/计数/推理）比堆同质数据重要
- **负样本必需**：不可答问题（"图里有几只鸟"图里没有）教会模型弃答——呼应 7-0 的 SQuAD 2.0 设计
- **拒绝采样**：用强 VLM 对生成答案打分过滤，是数据质量的标准动作（4-4 同款）
- **中文数据**必须单独构造（GPT-4 的中文图文描述质量不稳定，通常用 Qwen-VL 自举）

**版本纪律**：LLaVA-1.5 的预训练对齐数据与监督微调混合数据是不同阶段；不能把558K对齐集拼进665K指令集的构成。复现应下载对应版本的官方数据清单，记录各子集来源、去重和许可。

### 4. 训练阶段与灾难遗忘

三阶段课程（大模型标配）：

1. **投影对齐**：冻结全部，只训投影层，1~2 epoch
2. **视觉监督微调**：LLM 解冻（或 LoRA），混合多模态 + 少量纯文本数据防遗忘
3. **（可选）DPO 对齐**：多模态偏好数据（LLaVA-RLHF），用 6-1 的方法去幻觉

**灾难遗忘的量化监控**：每阶段后跑纯文本基准（MMLU/CMMLU）+ 视觉基准，文本掉 > 2 点即回调文本数据比例。**遗忘不是"会不会"而是"比例"问题——课程 2 的 10~20% 纯文本混入是标准解。**

### 5. worked example：7B VLM 的 anyres 显存账

**教学架构**：32层、8个KV头、每头128维；anyres为17格×576=9792视觉token，总上下文16384、batch4、BF16。这组数用于算账，不冒充某个具体模型的配置。

推理时，每元素2字节：

\[
M_{\mathrm{KV}}=2L n_{kv}d_h s B b_{\mathrm{elem}}
=2\times32\times8\times128\times16384\times4\times2
=8589934592\text{ 字节}=8\text{ GiB}.
\]

**训练是另一张账**：标准教师强制全序列训练通常关闭推理KV缓存，保存的是反向传播所需激活。不能把上面的8GiB作为额外推理缓存直接加到训练账里。全参训练还要计权重、梯度、主权重和优化器；LoRA主要减小可训参数相关的梯度和优化器状态，激活仍随长度、批大小与实现增长。

例如40M个LoRA参数仅Adam的两个FP32矩就需320MB，不是160MB；其他适配器状态另计。用真实峰值测量比较序列截断、视觉压缩、激活重计算和卸载，再决定单卡/多卡方案。
