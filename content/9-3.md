## why

图像是二维张量，视频是**三维张量 + 时序依赖**，音频是一维波形 + 冗余采样。两者共同的问题是：**原生表示的数据率太高**——1 分钟 720p 视频 ≈ 1 GB，1 分钟 24 kHz 音频 ≈ 2.9 MB。塞进 LLM 的 token 序列前必须压缩，而压缩率与信息损失的权衡就是本单元的主线。视频侧讲 3D 注意力与帧采样策略；音频侧讲离散 token 化（EnCodec/RVQ）与语音对话的全双工管线。对 11-5 的端侧部署，音频还是延迟最敏感的模态。

## body

### 1. 视频的三重困境：时空联合建模

视频张量 \(F\times H\times W\times 3\)（\(F\) = 帧数）直接 ViT 化的代价：

\[
N_{\text{token}} = \frac{F}{t_p}\cdot\frac{H}{P}\cdot\frac{W}{P}
\]

1 分钟 30 fps 视频 = 1800 帧；即使每 4 帧合一（\(t_p=4\)）、448 分辨率、patch 14 ⇒ \(450\times32\times32 = 460{,}800\) token——**任何 32K 上下文的 LLM 都装不下**。三重困境及对策：

| 困境 | 现象 | 对策 |
|---|---|---|
| 时序冗余 | 相邻帧 95%+ 像素相同 | 帧采样（1~2 fps 均匀采样） |
| 空间冗余 | 单帧内背景大面积静态 | 关键帧 + 差分 ROI |
| 长度爆炸 | token 数随秒数线性涨 | 分层：粗（每 N 秒 1 token）+ 细（关键片段全帧） |

**分层 token 化**（LLaMA-Vid / Video-ChatGPT 的做法）：先用轻量编码器把视频压成"关键帧序列 + 时间戳描述"，LLM 先读时间戳决定读哪些细粒度 token——**这是 10-1 Agent"工具调用"思想在视频模态的重演**：粗排定位、细排理解。

### 2. 3D 注意力：Video Swin 的局部性

视频 Transformer 的两种注意力：

- **因式分解（factorised）**：空间注意力 + 时间注意力分开做（TimeSformer  Divided），复杂度 \(O((HW)^2\cdot F + HW\cdot F^2)\)——比联合 \(O((F\cdot HW)^2)\) 低一个量级
- **3D window（Swin 式）**：在 \((t,h,w)\) 小立方体窗口内做注意力，窗口间 shifted——把 1-0 的局部性先验从 2D 推广到 3D

**工程结论**：长视频用因式分解或分层，短视频（<10 s）才能负担全 3D 联合注意力。Video Swin 的窗口移位机制使参数量与分辨率解耦——这对 9-2 的动态分辨率思路兼容。

### 3. 音频：从波形到 token 的量化管线

**神经音频编解码（EnCodec/SoundStream 路线）**：编码器把 24 kHz 波形下采样到离散 token 流：

1. 卷积下采样（stride 320 ⇒ 75 Hz 帧率）
2. **残差矢量量化（RVQ）**：第一级量化残差、第二级量化残差的残差……共 \(n_q\) 级。每级码本 \(2^B\) 项 ⇒ 总比特率 \(n_q\times B\times 75\) bit/s。EnCodec 典型配置 \(n_q=32, B=10\) ⇒ **24 kbps**
3. 解码器从 token 重建波形

**为什么 RVQ 而不是单级大码本**：码本大小 \(2^{B_{\text{total}}}\) 随比特数指数增长，搜索与训练都不可行；RVQ 把指数拆成 \(n_q\) 个小的，逐级精化；RVQ是逐级残差量化，不等同于模拟低精度数值误差的QAT。

**语音对话的全双工管线**：

\[
\text{波形} \xrightarrow{\text{VAD}} \text{EnCodec token} \xrightarrow{\text{ASR/语义 token}} \text{LLM} \xrightarrow{\text{LM} \to \text{token}} \text{vocoder}
\]

延迟预算（端到端 < 1.5 s 目标）：VAD 端点检测 200 ms + 编码 50 ms + LLM 首 token（8-7 的 TTFT）300~800 ms + 流式 vocoder 首帧 100 ms。**打断（barge-in）处理**：播放 TTS 时用户插话 ⇒ VAD 触发 ⇒ 清空播放队列 + 上下文追加——这是 6-6 异步 RL 的"抢占"思想在对话系统的应用。

### 4. worked example：1 分钟视频问答的 token 预算

**需求**：输入 60 s 720p 视频 + 文本问题，输出答案；上下文 32K。

**方案 A（密集采样，不可行）**：2 fps × 60 s = 120 帧 × 576 token/帧（336 分辨率）= 69,120 token > 32K ⇒ **超预算**。

**方案 B（均匀稀疏 + 关键帧）**：0.5 fps 均匀采样 30 帧 × 576 = 17,280 token + 5 个关键帧全分辨率（anyres 2×2 = 5×576=2,880/帧）≈ 14,400 ⇒ 合计 31,680 ≈ 预算极限 ⇒ **可行但文本和输出余量很小，需按实际窗口计数**。

**方案 C（分层）**：轻量编码器（每 2 s 压 32 token）⇒ 60 s / 2 s × 32 = 960 token 粗索引；读粗索引定位 3 个相关片段，每片段细化解码（5 帧 × 576 = 2,880）⇒ **总 9,600 token，约余量 22K 给文本与生成**。

**方案 D（音频，同视频的音轨）**：60 s × 75 Hz = 4,500 帧 × \(n_q=8\)（低比特配置）= 36,000 token ⇒ 超预算 ⇒ 必须与视频共享预算或降到 \(n_q=4\) = 18,000。

**结论**：多模态系统设计的核心技能是**token 预算分配**——像 8-6 分显存一样分上下文。方案 C 赢在把"全序列理解"换成"两阶段检索式理解"，代价是需要训练 LLM 会用粗索引（指令数据里加入"先定位后细读"的任务样本）。

%%%

假设每帧缩放到448×448，每帧 \((448/14)^2=1024\) token。120秒×1fps得122880 token；1080p源分辨率不再进入该缩放后的公式。即使已采样仍超过32K，需要更稀疏采样、空间压缩或分段检索。

**练习 2（对应退出标准 2）** 比较因式分解注意力与 3D window 注意力的复杂度，各适用什么视频长度？

%%%

每帧P个空间token、F帧时，分解注意力约 \(O(FP^2+PF^2)\)；固定窗口W个token时局部注意力约 \(O(FPW)\)，另有跨窗口传播代价。分解式仍有F平方项，长视频通常要窗口或层次压缩，不能只按10秒阈值选。

**练习 3（对应退出标准 3）** 解释 RVQ 为什么比单级大码本可行。EnCodec 32 级 × 10 bit @ 75 Hz 的总比特率是多少？

%%%

多个小码本逐级拟合残差，避免一个指数级大码本的存储与搜索。32×10×75=24000 bit/s=24 kbps；协议开销另计。若把各码本索引串行喂LLM，token速率与比特率是不同单位。
